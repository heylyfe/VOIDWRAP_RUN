# v0.34.0-alpha.1 — Refinement Cycle 22

Proof cycle. Cycle 21 restored the pedestal vote to the client; this one asked how anyone
would know it worked, and found that **nothing had ever opened a real vote session** — and
that the same "exists but never reaches the player" defect had left 615 lines of dead code
in the client, kept alive by their own passing tests.

## T-150 — no test ever opened a real vote session

| kit | what it covered |
|---|---|
| `voting-conformance` (default) | ten checks against a **stub** server |
| `voting-conformance --real` | Welcome, RunState, and a ballot rejected outside a session |
| `playthrough` | `vote` is **SKIP** — the bot never reaches level 2 |

The mechanic could have been broken in the wiring between `open_vote_session` and the wire
with every gate green.

New `tools/vote-integration/run.mjs` drives a real run with the frozen debug manifest —
`switch_level` to 2, `grant_gift` until `gifts_left=0` (which is exactly when
`open_vote_session` fires) — then ballots and asserts the whole round trip:

```
PASS - vote-opens (VoteOpen level=2 options=3 countdown_s=20)
PASS - ballot-counted (VoteState counts=[0,1,0] seconds_left=20)
PASS - result-names-the-ballot (VoteResult winner=1 (balloted 1) id=rewind permanent=true)
```

**The ballot decides, not the RNG.** `VoteSession::resolve` falls back to a seeded RNG when
every option ties — which is what happened before T-149. Balloting each slot in turn:

| `--option` | counts | winner |
|---|---|---|
| 0 | `[1,0,0]` | `pallbearer` |
| 1 | `[0,1,0]` | `rewind` |
| 2 | `[0,0,1]` | `lantern_leech` |

Three different winners from three different ballots.

## T-151 — 615 lines of dead code kept alive by their own tests

| module | lines | superseded by |
|---|---|---|
| `scene/checker.ts` | 466 | `scene/platformShaders.ts` (world-space procedural checker) |
| `shop/shopPanel.ts` | 149 | `hud/ShopPanel.tsx` |

Both had passing tests. **A test that imports a module is still an import**, so the suite
reported 11 green tests for code no player could reach.

Deleted both, and added `moduleWiring.test.ts`: every non-test `.ts`/`.tsx` under `web/src`
must be imported by another non-test file or be on an allowlist with a written reason.
`app/` route files are importers but never need to be imported. The allowlist has two
entries — `enemyPalette.ts` (a measurement helper by design) and `LobbyPoll.tsx` (a
deliberate deferral) — and a second test fails on a stale entry. Planting an orphan fails
the guard by name.

**Test count 342 → 333.** Eleven deleted with the dead modules, two added for the guard. A
lower count with the same coverage is the point.

## Tuning notes

- **The vote is now proven, not just wired.** If the game feels softer than before Cycle 21,
  the cause is player agency in the pedestal vote, not a bug — and it is now measurable
  rather than assumed.
- **`LobbyPoll.tsx` is the last allowlisted orphan.** It is the lobby variant of the vote.
  Whether the lobby should also have a vote surface is a design decision, not a wiring fix.
- **The playthrough's `vote` and `shop` checks are still SKIP** for the same reason as
  before (the bot cannot finish a level). `vote-integration` now covers the vote directly,
  so the skip no longer means "untested".
