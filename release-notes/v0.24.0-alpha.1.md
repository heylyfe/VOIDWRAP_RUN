## `hazard:trampoline` was a tag the engine did not keep

The economy audit's own closing line reads *"a tag with no entity is a promise
the engine does not keep"*. Two of the three `hazard:trampoline` patterns
carried **`JUMP_PAD`**, not `TRAMPOLINE`:

| pattern | tags | platforms |
| --- | --- | --- |
| `pa_garden_bounce` | `mech:bounce`, `hazard:trampoline`, `pad` | NORMAL, **JUMP_PAD**, NORMAL |
| `pa_machine_bounce` | `mech:bounce`, `hazard:trampoline`, `pad` | NORMAL, **JUMP_PAD**, NORMAL, **JUMP_PAD**, NORMAL |
| `ch24_cinder_switchyard` | `hazard:trampoline` | NORMAL, JUMP_PAD ×3, **TRAMPOLINE** |

A jump pad and a trampoline are different hazards with different arcs. Anything
that reads the tag — the pedestal curse options, the Extreme/Chaos frequency
tables, the radar module — was being told the wrong thing.

Both patterns gained a real `TRAMPOLINE` platform in the gap their jump pad
already launched across, so the bounce chain reads as intended rather than the
tag being quietly dropped. `hazard:trampoline` **1/3 → 3/3**.

## The playthrough bot: built, measured, parked

The last three dark checks (`level-progression`, `vote`, `shop`) all hang off
the bot completing a level, so this cycle built the platform graph they need:
`maxGapForRise` mirrors `design_max_gap`, `buildPlatformGraph` links platforms
whose edge-to-edge gap fits the envelope, and `platformUnder` / `nearestOn` /
`nextHop` give a BFS route so the bot aims at the next platform instead of
straight at the gift. `nearestLanding` adds air control while airborne.

**It did not produce a measurable win.** Five 60-second runs, 8 clients, fresh
server each time:

| build | gifts collected (best client, of 88) |
| --- | --- |
| before the graph | 39 |
| graph + air control | 41, 35, 33 |
| graph, jump probe capped at 4.0 u | 37, 29 |
| graph, landing search capped at 4 u below | 28 |

The spread between runs is larger than the difference between builds. The bots
still die to the void in every run, and capping the probe range, capping the
drop it will accept, and adding air control all left the death count at 6–8 of
8. The deaths are somewhere the probe does not cover.

Parked rather than pushed further. The next attempt needs a measurement first:
log the position and velocity of each `DEATH_VOID` server-side, then look at
where they actually fall. The graph code stays — it is correct and it is the
foundation that attempt needs.
