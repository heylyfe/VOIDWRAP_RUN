# v0.33.0-alpha.1 — Refinement Cycle 21

Wiring cycle. Cycle 20 separated the enemies by colour; this one asked the same question
of everything else that has an identity — the player's class, the enemy roster's shape,
and the vote — and found that **two of the three were never reaching the player at all.**

## T-149 — the pedestal vote had a complete client UI that nothing mounted

The server opens a vote session every level at the collapse window, broadcasts `VoteOpen` /
`VoteState` / `VoteResult`, and accepts `ClientMsg::Vote`. The client had `VoteWidget`,
`useVote`, `protocolAdapter`, `RunVoteOverlay` and `LobbyPoll` — every one of them tested,
**none of them mounted**. `session.ts` had no method that could send a ballot.

So the vote ran every level, invisibly, and `VoteSession::resolve` fell through to its last
resort: with zero ballots every count is 0, every option ties, the host has no ballot, and
the RNG picks. **Players gained a random permanent every level and were never shown the
choice.**

`store.ts` gains a capped `voteMessages` log, `session.ts` records the three messages and
gains `vote(option)`, and `GameClient` mounts `RunVoteOverlay` against both. The overlay
returns `null` outside a vote, so nothing changes for a player who is not voting.

`protocolAdapter.ts` had been written against *assumed* field names while T-078 was in
flight, and said so in its header. The real protocol sends `countdownS` and `secondsLeft`,
not `durationMs` / `remainingMs`, so the countdown would have shown the local 20 s default
instead of the server's. Both spellings are accepted now.

## T-147 — the striker's class colour never reached the screen

`classColor()` is called by `GliderWings`, `GrappleLine` and `WardDome`. Nothing called it
for `CLASS_STRIKER`: `GameClient` rendered the dash streak as `<DashStreak
color={theme.accent} />`, so `CLASS_COLORS[CLASS_STRIKER]` was dead code and the striker's
ability visual was magenta on ashfall, pure magenta on fluxbloom, dark red on slagstone and
teal on tidegrave — **64.8 to 149.0 delta-E from the colour it was supposed to be.** Three
classes had a stable identity colour; the striker's changed with the level.

No colour was changed. The measurement said the palette is fine — closest pair
striker/grappler at 25.7, worst fog contrast 52.5 — and that the search for a better pair
lands 17.9 from `blight`'s accent (green) or 12.2 from `turret`'s (orange). The space is
saturated by 20 enemy accents plus the straggler beam.

## T-148 — a check that compared placements to levels could never fail

`6.enemy-frequencies.always-offered` exists to catch a `(mode, level)` cell where one enemy
type is offered in 100% of levels. It compared `cell.byType` — a **placement** count —
against `cell.levels`. A level carries several spawn markers, so placements always
exceeded levels: **3200 against 400** on the 400-seed dump. The equality could only hold if
every level had exactly one enemy, which never happens.

It reported PASS on every run since it was written while measuring nothing. This is the
defect class T-144 fixed elsewhere in the same file, in a check T-144 itself touched: it
removed the `byType.size >= 2` filter that was hiding the single-type case, but left the
units mismatch underneath, so removing the filter changed nothing.

`consumeRecord` now also fills `cell.levelsWithType` and the check compares that against
`cell.levels`. Two more holes closed while in there: a run where no cell reaches the
minimum level count would have reported PASS having examined zero cells, and the dump's
generic `spawn` marker — present in every level by construction — would have made the fixed
check fire on every run for a reason that is not a defect. Both now SKIP with the reason.

Real dump: 17 lines, 0 failed, **2 skipped** (was 1 pass + 1 skip).

## Tuning notes

- **The vote now has player agency, which changes the difficulty curve.** Before this
  release the server picked a random pedestal every level; now the team picks. Expect runs
  to get easier at first because a coordinated team will take the option it can handle.
  This is the intended behaviour, but it is a real balance change and the first thing to
  look at if the game feels softer.
- **`LobbyPoll` is still unmounted.** It is the lobby variant of the vote and the lobby
  already has `DraftScreen` for card picks; mounting both would put two vote surfaces on
  screen. Deleting it is a separate decision.
- **The dump still cannot answer per-enemy variety.** `6.enemy-frequencies.*` both SKIP
  because the dump carries generic `spawn` markers. Making it carry real enemy types needs
  the pedestal-pool logic, which lives in the `server` crate while the dump lives in `sim`
  — a crate-boundary decision, not a polish diff.
