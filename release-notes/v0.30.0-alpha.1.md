# v0.30.0-alpha.1 — Refinement Cycle 18

One check added, one change reverted. The revert is the more useful half.

## Reverted: the bot's hold-still fallback

Cycle 16 found that the playthrough bot's edge probe fails by blacklisting the gift and
standing still, so a bot whose remaining gifts are all behind unprobeable gaps freezes
for the rest of the run. The obvious fix is to walk back toward the middle of the
platform underfoot instead.

Implemented and measured over two 8-client 90 s runs:

| | best client's gifts |
|---|---|
| baseline | 40/88, 44/88 |
| with `retreat` | 25/88, 42/88 |

**No measured win**, so it was reverted. The freeze is real but it is not what limits
gift collection — the limiter is the 6–7 deaths per run against 0 starting lives.

## Added: `gift-rate`

`level-progression` needs a completed level, which the bots cannot reach, so it is
permanently skipped. That left level traversal with no signal at all: a change that made
levels much harder to move around would not fail anything.

`gift-rate` asks the question that needs no completion — can the bots still move around
and pick things up?

```
PASS - gift-rate (best client collected 33/88 gifts (37.5%) in 90s; threshold >= 20%)
```

Measured 28–50% across runs, so the 20% floor leaves headroom for variance while still
failing if traversal degrades. Negative-tested at 90%: `FAIL - gift-rate`, `8/12 checks
passed`.

## Tuning notes for the later balancing pass

- **Starting lives = 0** is still the single largest obstacle to automated coverage, and
  it is now the *only* one for the playthrough: the freeze hypothesis was tested and
  ruled out.
- `gift-rate` at 37.5% is a baseline. If a difficulty change drops it below 20%, levels
  have become meaningfully harder to traverse.
