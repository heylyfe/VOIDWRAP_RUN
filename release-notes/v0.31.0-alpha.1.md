# v0.31.0-alpha.1 — Refinement Cycle 19

Audit-honesty cycle. No gameplay change: two tickets, both about the audit tools
telling the truth about what they measured.

## T-143 — `5.reference-scale` reports a measurement, not a guess

The metric printed a `minExtent` field claiming the footprint the ramp slope cap
*forces* (`2 * drop / RAMP_MAX_RISE_RUN`). It was wrong for two of the three
out-of-band patterns:

- `ch15_tri_crown` has **no ramp covering its drop at all** — it is a stepped
  terrace (0 → −2.5 → −3.5). The old field claimed it was forced to 26 u when its
  actual footprint is 25 u, i.e. it claimed the chunk was smaller than the minimum
  it was supposedly forced to be.
- `ch04_twin_terrace`'s ramps sit **inside** its 22 u deck; nothing forces the deck
  to be 22 u.

Replaced with `maxPlatform`, the largest single platform's XZ extent. That
separates "big because it is composed of many pieces" (`ch06`: 30 u footprint,
8 u largest platform) from "big because one deck is oversized" (`ch04`: 22 u
footprint, 22 u largest platform). Rate unchanged at 2.11%.

## T-144 — a metric with nothing to measure no longer reports PASS

Every rate metric was written `denom ? viol / denom : 0` then asserted
`rate <= MAX`, so a zero denominator produced a PASS having measured nothing.
Eleven metrics had this shape.

The fix separates two cases that `Number(rec.x ?? 0)` conflates:

| case | verdict |
|---|---|
| field absent from every record | **SKIP**, naming the field |
| field present, total is zero | **FAIL** |
| denominator zero for a structural reason | **SKIP**, naming the reason |

Also fixed in the same pass:

- `7.catalog-coverage` emitted a **PASS line whose text began "SKIP"** — historical
  defect #4 verbatim, on the metric built to catch T-132
- `6.enemy-frequencies.always-offered` filtered out `byType.size < 2`, so a single
  type appearing in 100% of a cell's levels escaped the check for exactly that
- `2.tag-diversity` counted unknown forward-compat tags toward mean/min, so an
  unknown tag inflated the score the metric exists to guard
- `3.anchor-fallbacks` could not tell a missing field from zero fallbacks
- `1.pattern-repeat.across-seeds` was vacuous with a single seed
- `5.stairs` used a counter that only increments when a chain is *found*, so it
  could not tell "no stairs exist" from "nothing was checked"
- economy `8.hazard_entities` passed a hazard tag with **zero** tagged patterns
- economy `6.radar_offering` did not check the three ids were distinct
- economy `2.shop_offer_mix` printed `SHOP_OFFER` rather than the real offer, and
  its `>= 4` floor was dead code

The `RESULT` line now prints the skipped count, so a SKIP cannot be mistaken for
coverage in a log skim.

### The selftest had been failing unnoticed

`node tools/pattern-audit/run.mjs --selftest` was reporting **FAIL** on `main`
before this cycle: `7.catalog-coverage` trips on the synthetic records' ids, and
the expected-failure set never learned about that metric. Nothing gated
`--selftest`, so it rotted. The catalog is now injectable, and `--selftest` is
part of `just verify`.
