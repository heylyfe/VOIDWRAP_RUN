## T-152 — silhouette distinctness, measured on rendered pixels

Cycle 22 parked this because the only way to measure it was to read the model sources, and that
measures the wrong thing: the models are animated JSX with conditional rendering, refs and
instanced meshes. The owner's ruling was to build the measurement instead of guessing.

New dev-only route `/dev/enemies` renders one enemy at a time against a flat background, and
`tools/silhouette.mjs` drives it, takes the pixels that differ from the background as the
silhouette, and compares every pair with IoU.

**Excluded from production by construction.** `next.config.ts` drops `dev.tsx` from
`pageExtensions` when `NODE_ENV === "production"`, so the route does not exist in a release. A
real build lists only `/`, `/_not-found` and `/play`; `out/dev/enemies/index.html` is absent and
the component is not in the bundle at all.

Two measurement bugs were caught by reading the numbers rather than trusting the first green run:

- **A head-on camera renders LURE as nothing.** LURE is a flat ground-plane creature, so a
  camera at `[0, 0, 6]` saw it edge-on as a zero-height line. The camera now sits at
  `[0, 2.6, 5.0]`, which is also the projection the player actually gets.
- **Normalising the bounding box threw away size.** A 1.3-radius Pallbearer and a 0.5-radius
  Mimic both became "a solid rectangle" and scored **0.948** — a false collision. The game
  scales every model by its body radius, so the gallery now applies the same scale and the tool
  compares exact pixel masks in a fixed frame.

Result over 190 pairs: `min 0.000  p25 0.129  median 0.245  p75 0.339  p90 0.432  max 0.780`.
The roster is well spread. `MAX_IOU = 0.82` is a regression guard anchored to the shipped
roster, not a perceptual constant, and `--selftest` proves the gate can fail (6/6).

## T-153 — `LobbyPoll` promised a feature that does not exist

The parking note said to wire it into the new physical lobby or delete it. Neither branch
applied: T-120 is not a physical lobby (it is the ticket that made the dev code default to
`devaccess`), and `LobbyPoll` is a *pre-match theme/difficulty poll*, not the pedestal vote.

It is **unimplemented, not superseded**. Its copy claims theme and difficulty picks "feed the
pattern engine's tag weights", and there is no `Poll` message in the protocol and no server
handler for one. Deleted, with its two tests and its allowlist entry. A pre-match poll is a real
feature idea, but it needs `just gen` + `just fixtures` and is logged as a candidate rather than
smuggled into a cleanup.

## T-154 — the playthrough bot, actuated through the debug layer

`level-progression`, `vote` and `shop` had been SKIP on every run since T-139, because the bots
cannot complete a level. `--actuate` now runs a singleplayer session and drives the run through
the frozen debug manifest — `switch_level`, `set_phase`, `grant_gold`, `Buy`, `grant_gift` —
while the bot keeps walking. `verify-live` runs both passes.

All three are **live checks** now:

```
PASS - actuate-shop (Shop frames: 2, items: 10, stocked: 10, bought short_fuse for 426)
PASS - actuate-level-progression (level 2: ok=true freshLevel=true gifts=56 stateLevel=2; level 3: ...)
PASS - actuate-vote (gifts_left=0, VoteOpen=true, options=3)
PASS - level-progression (level went 1 -> 3 (best client collected 66/66 gifts))
PASS - vote (VoteOpen frames: 1)
PASS - shop (Shop frames: 3)
```

Four measurement bugs surfaced while building it:

1. **`level-progression` was passing on stale frames.** The server pushes its run state on
   `Hello` and `Restart` only resets a run that is *over*, so a server left at level 3 by an
   earlier sweep reported `highest level reached: 3` for a sweep that advanced nothing. The
   check now asks whether the level **changed** (`level went 1 -> 3`), not whether it is high.
2. **The bot bought into a closed shop.** A `Shop` frame is sent whenever the offer changes,
   including for a level already playing, and a `Buy` outside `PHASE_ENEMY_DRAFT` is a 409. The
   `error-frames` check caught it; auto-buy is gone and the driver sets the phase explicitly.
3. **The shop step deadlocked on its own capture point** — it waited for a `Shop` frame after
   the jump that generates it.
4. **`draft` and `class-select` blamed the server for the sweep's own timing.** Both only exist
   in the first lobby, so both now SKIP with the reason.

Negative test: with `--code nope` every actuated check fails, the rate limiter fires, and
`level-progression` SKIPs rather than false-passing.
