# Ticket T-024: Starter draft content (enemies, upgrades, curses) + per-theme screen grades
Target: INKLING-DESIGN

## Context
VOIDWRAP RUN is a fast 3D roguelite collectathon platformer. Each level is a cluster of floating checkerboard
platforms in a coloured misty void. The player collects 5 gifts, then reaches an exit beacon to go deeper; falling
into the void or touching an enemy ends the run. Player movement: run 9 u/s, jump velocity 12 (apex ~2.25 u, hold for
full height), gravity 32 u/s², dash 28 u/s for 0.15 s with a 0.75 s cooldown, coyote time 120 ms, jump buffer 100 ms.
Levels are ~40-60 units across. The server runs at 20 ticks/s.

We are adding a DRAFT flow:
- Pre-run lobby: the player is shown enemy cards and picks which enemies will hunt them this run (solo: pick 2 of 4
  offered; their behaviour and threat must be clear so the choice is informed, not a lottery).
- After every cleared level: pick 1 of 3 cards, mixing upgrades (help) and curses (hurt, but each curse grants +1 extra
  "draft reward" later; for now just describe it as "harder run, better rewards").
- Every 10th level: the 3 cards are greater curses (much stronger).

Right now only ONE enemy behaviour exists in code: a "chaser" that flies straight at the nearest player within an aggro
radius, ignores platforms, returns home when nobody is in range, is harmless during a spawn grace period, and kills on
touch (hit box = cube of half-size `size`). Enemy variety in this ticket must therefore be expressed ONLY as different
parameter sets of the chaser behaviour (later milestones add turrets, mimics, tile-corrupters).

EFFECT VOCABULARY - every upgrade/curse must be expressed ONLY with these keys (multipliers default 1.0, additive
counts default 0). Do not invent other keys.
- Player: `run_speed_mul`, `jump_mul` (jump velocity), `gravity_mul`, `dash_speed_mul`, `dash_cooldown_mul`,
  `air_jumps_add` (extra mid-air jumps, integer 0-2), `gift_radius_mul` (pickup reach), `extra_lives_add` (integer;
  a life respawns you at the level start instead of ending the run).
- Enemies: `enemy_speed_mul`, `enemy_aggro_mul` (aggro radius), `enemy_grace_mul`, `enemy_size_mul`,
  `extra_enemies_add` (integer: additional copies of a random drafted enemy per level).
- World: `fog_density_mul` (visual: distance you can see; >1 = thicker fog), `beacon_radius_mul`.
Sane ranges: multipliers 0.5-1.6 for upgrades/curses, greater curses may go to 0.4-2.0; no single card may make a level
impossible (e.g. jump_mul < 0.85 makes 1.5-unit steps unreachable; gravity_mul > 1.25 likewise; run_speed_mul < 0.8 makes
4-unit gaps unreachable - keep curses within those limits or pair them with compensation).

Screen grades: we have 4 colour themes, each a monochrome-ish world with neon accents:
- ashfall: pale grey storm clouds, lavender + near-black checker tiles, magenta sparks
- fluxbloom: deep saturated magenta haze, plum + black checkers, hot violet glow
- slagstone: neutral slate dusk, stark white + black checkers, blood-red danger
- tidegrave: deep teal underwater gloom, teal + navy checkers, cold cyan crystals
A full-screen colour-grade filter sits on top of bloom. Parameters per theme:
`tint` (hex colour), `tint_strength` (0-0.35, mixes the image toward tint in a soft-light way), `saturation` (-0.3..0.4),
`contrast` (-0.2..0.35), `brightness` (-0.15..0.1), `vignette_color` (hex), `vignette_darkness` (0.2-0.8),
`aberration` (0.0004-0.003 screen units), `grain` (0-0.08), `scanlines` (0-0.15 opacity of faint horizontal lines;
use only where it fits the mood).

## Task
Design, as JSON data, with ORIGINAL names and text (never reuse names or wording from any existing game):
1. `enemies`: 6 chaser-family variants. Each: `id` (snake_case), `name` (2 words max, evocative), `flavor` (one line,
   max 70 chars), `behavior` (one concrete line: how it moves, how fast relative to the player, when it wakes, how to
   counter it - max 110 chars), `threat` (1-5), `params` {`speed` u/s, `aggro` radius u, `grace_s` seconds, `size` half-extent u}.
   Spread them: a slow huge-aggro stalker, a fast short-range ambusher, a tiny quick one, a big slow one, etc.
   No variant faster than 8.5 u/s (the player runs at 9). Grace 1.5-5 s.
2. `upgrades`: 10 cards. Each: `id`, `name`, `flavor` (<=70 chars), `effect` (exact player-facing description with the
   numbers, e.g. "+15% run speed", <=60 chars), `rarity` ("common"|"rare"), `mods` {vocabulary keys only}.
3. `curses`: 10 normal curses + 3 greater curses (`greater: true`). Same fields as upgrades plus `threat` (1-5).
4. `grades`: one object per theme id with the parameters above, tuned to amplify that theme's mood (e.g. fluxbloom:
   magenta tint, saturated, slight scanlines; slagstone: desaturated cold, high contrast, red-tinged vignette...).
For every card, check your numbers against the playability limits above.

## Constraints
Output exactly ONE FILE block: `design/content.draft.json` containing an object with keys `enemies`, `upgrades`,
`curses`, `grades`. Valid JSON (no comments, no trailing commas). Then a NOTES block (<= 25 lines) explaining the
balance intent and anything you are unsure about. Do not wrap the file contents in markdown fences.

## Acceptance criteria
- [ ] Only vocabulary keys in mods; all numbers within the stated ranges and playability limits.
- [ ] Every card has the full description fields; text is original and fits the length limits.
- [ ] 6 enemies, 10 upgrades, 10 + 3 curses, 4 grades.
