# T-120 — Tester panel dev code defaults to `devaccess`

**Owner decision (2026-11-15):** "make the code be like: devaccess".

## What changed

`server/crates/server/src/debug.rs` gained:

```rust
pub const DEFAULT_DEV_CODE: &str = "devaccess";
```

`Gate::from_env` now falls back to it when `VOIDWRAP_DEV_CODE` is unset or
empty, and records that it did (`using_default`). `game.rs` logs a warning at
startup when the default is in use, so a build running on it is visible in the
log rather than assumed.

## How to use it

Open the panel with **Ctrl+Shift+D**, type `devaccess`, press Unlock.

Or skip the code entirely:

```bash
VOIDWRAP_DEV=1 just run
```

Or set your own:

```bash
VOIDWRAP_DEV_CODE=mysecret just run
```

## What this does and does not weaken

**Does:** anyone who reads the source can unlock a tester build. That is the
point of the change — the owner asked for a code they can remember without
exporting anything.

**Does not:** the other two gates are untouched.

- **Singleplayer only.** The server rejects every command while more than one
  player is connected. A tester build in a lobby is inert.
- **Rate limited.** Five wrong codes per connection, then that connection is
  locked out for its life even with the right code.
- **Still server-side.** The constant lives in the server crate. It is not in
  the protocol, not in the client bundle, and not in the manifest, so a client
  cannot learn it from the build it downloads. It is documented in
  `design/DEBUG_COMMANDS.md` because it is a server-side constant, not a
  secret.

## Tests

`the_default_code_opens_the_route_and_is_reported_as_a_default` — the default
opens the route, `using_default_code()` is true, `"devacc"` and `""` are both
refused. The existing `an_empty_configured_code_is_never_satisfiable` still
passes: an explicitly empty `VOIDWRAP_DEV_CODE` is filtered to `None` by
`Gate::new`, so "empty is never satisfiable" remains a property of the type.

## Docs

`design/DEBUG_COMMANDS.md` gate 1 now names the default and says why it is
documented. The frozen command list is unchanged — this is a gate
configuration change, not a manifest change.
