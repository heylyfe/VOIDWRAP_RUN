# T-161 — The poll panel: give the pre-match poll a face

**Cycle:** 25
**Status:** OPEN
**Area:** `web/src/hud/poll/` (new), `web/src/hud/PollOverlay.tsx` (new),
`web/src/game/session.ts`, `web/src/game/store.ts`, `web/src/game/GameClient.tsx`
**Model:** inkling-2-small-free, variant max

## Why this ticket exists

T-159 landed the pre-match poll's protocol, server and sim halves and **parked the client panel**.
That leaves the game in a state that must not ship: `poll_blocks_start()` gates the level-1 draft,
there are two polls (theme, then difficulty) at `POLL_COUNTDOWN_TICKS = 20 * TICK_HZ` each, and
nothing in the client renders or answers them. A player joining a fresh run sits through **40
seconds of dead time with no UI**.

This ticket is the release gate for the poll. If it parks, the poll gets gated off before the
release instead.

## What the server already sends

From `protocol/schema.json` (already generated into `web/src/protocol/generated.ts`):

```
ClientMsg::Poll        { option: u8 }
ServerMsg::PollOpen    { options: PollOption[]; countdown_s: u16 }
ServerMsg::PollState   { counts: u32[]; voted: u32[]; seconds_left: u16 }
ServerMsg::PollResult  { winner: u8; id: string; name: string; kind: u8 }
PollOption             { id: string; name: string; kind: u8 }
POLL_THEME = 0, POLL_DIFFICULTY = 1
```

`counts[i]` is the ballot count for `options[i]`. `voted` is the player ids that have voted.
`kind` on `PollResult` says which question resolved.

## What to build

Mirror the vote UI exactly — it is the shipped pattern and it already solved every problem this
panel has. Read `web/src/hud/vote/` (`model.ts`, `protocolAdapter.ts`, `useVote.ts`,
`VoteWidget.tsx`, `CountdownRing.tsx`) and `web/src/hud/RunVoteOverlay.tsx` before writing
anything.

1. **`web/src/hud/poll/model.ts`** — the panel's own state shape: the open question, its options,
   the counts, who has voted, seconds left, and the resolved result.
2. **`web/src/hud/poll/pollAdapter.ts`** — the only module that knows the wire shape. Accept both
   `countdown_s`/`countdownS` and `seconds_left`/`secondsLeft`, the way `vote/protocolAdapter.ts`
   does, because the generated TS uses camelCase and the Rust field names are snake_case.
3. **`web/src/hud/poll/usePoll.ts`** — a hook that ingests messages and exposes
   `{ state, sendPoll, ingestMessage, reset }`, mirroring `useVote`.
4. **`web/src/hud/poll/PollWidget.tsx`** — the panel. It must show the question (theme or
   difficulty, from `kind`), each option with its live count, the countdown, and the result when
   one arrives. Reuse `CountdownRing`.
5. **`web/src/hud/PollOverlay.tsx`** — the mount point, mirroring `RunVoteOverlay`: props
   `{ onPoll?, messages?, onRevealDismiss? }`, replaying `messages` through `usePoll`.
   **It must render `null` when no poll is open** — no empty box, no placeholder.
6. **`web/src/game/session.ts`** — add `PollOpen` / `PollState` / `PollResult` to the message
   switch, appending to a new `pollMessages` store array (cap it at 64 like `voteMessages`), and
   add `poll(option: number): void` sending `{ type: "Poll", option }`. Note this file is **CRLF**;
   preserve its line endings.
7. **`web/src/game/store.ts`** — `pollMessages: unknown[]`, initial `[]`.
8. **`web/src/game/GameClient.tsx`** — mount `<PollOverlay messages={pollMessages} onPoll={(option) => session?.poll(option)} />` next to `RunVoteOverlay` (around line 448).

## Tests

- `web/src/hud/poll/__tests__/poll.test.ts` — the adapter accepts both spellings; the hook
  ingests open/state/result; the widget renders the options and their counts; the widget renders
  nothing when closed.
- `web/src/game/pollWiring.test.ts` — **the important one.** Mirror `voteWiring.test.ts`: assert
  that `GameClient.tsx` imports `PollOverlay` and mounts it with a `messages=` prop, and that
  `session.ts` handles all three `Poll*` variants and has a `poll(` method. T-149's whole lesson
  was that a component can exist, be tested, and never be mounted; this test is what stops that
  happening again.

## Rules

- **New files plus additive edits.** Do not refactor `vote/` or `RunVoteOverlay`.
- vitest only collects `src/**/*.test.ts`, **not** `.tsx`. Put tests in `.ts` files.
- `just verify` is the gate. `npx tsc --noEmit` and `eslint .` must be clean in `web/`.
- No new dependencies.
- **Anti-rabbit-hole: 3 attempts on a sub-problem, then park it and say so.** If the panel fights
  you, a minimal panel that renders the options, sends `Poll`, and hides when closed is enough —
  the countdown ring and the result reveal are polish, not the gate.
- Document every choice in the ticket. No human is available.

## Done when

A player joining a fresh run sees the theme poll, can vote, sees the counts move, then sees the
difficulty poll, and the level starts. The panel renders nothing when no poll is open. The wiring
test proves it is actually mounted. `just verify` is green.
