# T-103 — Playthrough navigation bot (tools/playthrough)

**Agent:** `model:acpRegistry_mistral_vibe/deepseek-v4`, max effort.
**Scope:** `tools/playthrough/` only. Do not touch `server/`, `web/`, or `design/`.

## Why

The automated playthrough sweep is the only end-to-end signal in the repo, and it
currently stalls at level 1. Baseline at `v0.17.0-alpha.1`:

```
PASS - connect (8/8 clients connected)
PASS - welcome (Welcome frames: 8)
PASS - runstate (RunState frames: 40)
FAIL - level-progression (highest level reached: 1)
SKIP - draft (Draft frames: 8)
SKIP - vote (VoteOpen frames: 0)
SKIP - shop (Shop frames: 0)
PASS - phase-coverage (distinct phases: 2 [0,1])
PASS - decode (0 undecodable frames)
PASS - class-select (0/8 clients had their class rejected)
PASS - error-frames (0 unexpected Error frames)
playthrough: 7/11 checks passed, 3 skipped (level never completed)
```

The bot random-walks (`Client.startWalking`), so it never collects the gifts a level
requires and the level never completes. Three checks are SKIPped as a direct result and
`level-progression` FAILs. Fixing this turns 7/11 into 11/11 and gives every later
refinement cycle real coverage of draft, vote and shop.

## What the bot can see

`ServerMsg` has a `Level` variant carrying the full `LevelData`:

```
Level -> [["data","LevelData"]]
```

`LevelData` (see `server/crates/protocol/src/generated.rs`) has `spawn`, `beacon`,
`kill_y`, `platforms: Vec<Platform>` (`{id: u16, kind: u8, bounds: Aabb}`), and
`gifts: Vec<Gift>` (`{id: u16, pos: Vec3, kind: u8}`). `Aabb` is `{min: Vec3, max: Vec3}`.

So the bot knows every gift position and every platform box. `Snapshot` carries
`you: ControllerState` with the player's position. Use those two.

## Required behaviour

1. **Capture the level.** On `Level`, store `data`. On `Snapshot`, read `you.pos`.
2. **Steer to the nearest uncollected gift.** Each tick, pick the nearest gift in
   `data.gifts` that is not yet collected (a gift disappears from the level once taken;
   if the server does not resend `Level`, treat a gift as collected when the player has
   been within 1.5 u of it and it is no longer in the nearest set — simplest correct
   approach: recompute the nearest each tick and let the player walk into it).
3. **Convert a world direction into `Inputs`.** `Inputs` frames are
   `{seq, move_x, move_z, buttons}` with `move_x`/`move_z` in `-127..=127`. Normalise the
   horizontal direction to the target and scale to 127. Set `buttons` bit 0 (jump) when
   the target is more than 0.5 u above the player and the player is grounded, and when a
   horizontal gap ahead is wider than 2 u.
4. **Fall back to the random walk** when no `Level` has arrived yet, so the sweep still
   exercises movement on a server that never sends one.
5. **Keep the existing autopilot.** `Client.react` already answers `Draft`, `VoteOpen`
   and `Shop`. Do not change those handlers.
