# T-092 — Tag the 25 legacy chunks so the composition engine can see them

**Agent: `model:opencode/opencode/inkling-2-small-free` (max effort).**

A pure data edit, fully specified below. Do not ask questions.

## The measured problem

`tools/pattern-audit` over 3,000 generated levels reports:

```
PASS - 0.input (... levels on the §6.4 no-tag fallback path: 3000)
FAIL - 2.tag-diversity.mechs (vocabulary coverage 9/10 values used (never offered: dead_end))
FAIL - 4.near-duplicates (606/3000 levels (20.20%) have a near-duplicate pair; threshold <= 0.2%)
```

**Every single level is on the no-tag fallback path.** The cause is in
`design/chunks.json`: its 25 chunks carry descriptive tags like `["lift",
"jump_pad", "tower"]` but no `theme:*` or `mech:*` tags. The composition engine
selects by theme and mechanic, so an untagged chunk is invisible to it and the
level falls back to the legacy walk. That also explains `dead_end` never being
offered: the three `dead_end` chunks are all untagged.

The fix is **additive only**: append `theme:` and `mech:` tags to each chunk's
existing `tags` array. Never remove or rename an existing tag.

## The vocabularies (frozen — do not invent values)

- mechs: `climb`, `drop`, `span`, `bounce`, `crawl`, `gauntlet`, `rest`, `loot`, `fork`, `dead_end`

## Output format

`design/chunks.json` is one JSON object per line inside a `{"version":1,"chunks":[...]}`
wrapper, with a trailing comma on every line but the last. You cannot reproduce the
whole file, so emit a **patch list**:

```
=== PATCH: design/chunks.json ===
ch01_sundered_gate: tags += ["theme:ruin", "mech:rest"]
ch02_hollow_market: tags += ["theme:hollow", "mech:rest"]
...
=== END PATCH ===

=== NOTES ===
<any judgement calls, e.g. why a chunk got one theme over another>
=== END NOTES ===
```
