# Ticket T-042: Level events, crumbling platforms and altars in the level generator
Target: INKLING (max effort)

## Context
You wrote `sim::levelgen` earlier (procedural roads of checkerboard platforms, a hop-envelope validator, every level
proven completable by a physics bot). M2 adds level events and altars. Protocol v6 has `LevelData.event`
(EVENT_NONE / EVENT_HIGH_RISE / EVENT_ICE / EVENT_CRUMBLE), `LevelData.altars: Vec<Altar { id: u16, pos: Vec3 }>` and
`Platform.kind` PLATFORM_NORMAL (0) / PLATFORM_CRUMBLE (1). Right now every generated level has event EVENT_NONE,
no altars and only normal platforms.

## Task
1. Event choice, deterministic from (seed, level): level 1 and `hub()` are always EVENT_NONE. For level >= 2,
   35% of levels get an event, picked uniformly from HIGH_RISE, ICE, CRUMBLE. Expose
   `pub fn event_for(seed: u32, level: u32) -> u8` and use it inside `generate`.
2. EVENT_HIGH_RISE: the level climbs. Bias the road builder so that height steps up occur clearly more often (aim
   for the beacon at least 6 units above the spawn on most seeds), staying inside the existing hop envelope so
   `validate` still passes and nothing becomes impossible. Keep gifts reachable as today.
3. EVENT_CRUMBLE: mark about 40% of the platforms as PLATFORM_CRUMBLE, never the spawn platform (id 0), never a
   platform holding a gift or the beacon, and never so many in a row that a road could only be crossed over
   crumbling tiles more than 3 platforms long (crumbled tiles come back after 3 s, but keep it fair).
4. EVENT_ICE changes nothing in geometry (the server lowers friction); just set the event.
5. Altars: from level 3 on, 50% of levels get one altar (deterministic from seed/level), standing on top of a
   platform (pos.y = platform top), at least 3.0 units horizontally from every gift, the beacon, the spawn point and
   every enemy spawn, and fully on the platform (at least 0.75 from its edges). Ids start at 1. If no platform
   qualifies, no altar. The altar must not be on a PLATFORM_CRUMBLE platform.
6. `validate` additionally checks: event value is one of the four, altar rules from 5, crumble rules from 3.
7. Tests: event distribution over 400 seeds is roughly 65/35 for level >= 2 and always NONE for level 1;
   high-rise beacon height (median over 100 seeds >= 6.0 above spawn); crumble count and exclusions; altar spacing;
   determinism (same seed/level -> identical LevelData); all generated levels pass `validate` for 200 seeds x
   levels 1..=12; the fallback rate stays at or below 2%.

## Constraints
Only `server/crates/sim/src/levelgen.rs` (complete file). Keep the public API (`hub`, `generate`, `validate`,
`GeneratedLevel`, `NORMAL_GIFTS`) source-compatible.
