# T-151 — 615 lines of dead code kept alive by their own tests

**Cycle:** 22
**Status:** PASS
**Area:** `web/src/scene/checker.ts`, `web/src/shop/shopPanel.ts` (deleted), `web/src/moduleWiring.test.ts` (new)

## What was wrong

Sweeping the client for the defect T-149 found — a piece that exists and never reaches the
player — turned up two modules that nothing imported:

| module | lines | superseded by |
|---|---|---|
| `scene/checker.ts` | 466 | `scene/platformShaders.ts` (world-space procedural checker) |
| `shop/shopPanel.ts` | 149 | `hud/ShopPanel.tsx` |

Both had passing tests. **A test that imports a module is still an import**, so the suite
reported 11 green tests for 615 lines of code no player could reach. The tests were not
wrong; they were testing a thing that had been replaced.

`checker.ts` was the texture-based checkerboard. `Platforms.tsx` now says, in a comment at
the exact place the old module would have been used: *"No uv attribute: the surface shader
checkers from vWorldPos.xz"*. The replacement is documented; the original was never
removed.

## The fix

1. **Deleted both modules and their tests** — 615 lines and 11 tests that proved nothing
   about the shipped game.
2. **Added `web/src/moduleWiring.test.ts`**, the general form of the guard: every non-test
   `.ts`/`.tsx` under `web/src` must be imported by at least one other non-test file, or be
   on an explicit allowlist with a written reason. Next.js `app/` route files are importers
   but never need to be imported themselves.
3. **The allowlist has two entries**, each with a reason:
   - `scene/enemyPalette.ts` — CIELAB + delta-E maths, a measurement helper by design.
   - `hud/LobbyPoll.tsx` — the lobby variant of the vote; the lobby already has
     `DraftScreen`, so mounting both would put two vote surfaces on screen. Deleting it is
     a human decision, not a wiring fix.
4. **A second test keeps the allowlist honest**: an entry for a module that no longer exists
   fails, so the list cannot rot into a set of stale promises.

## Evidence

**Negative test.** Planting `web/src/scene/orphanProbe.ts` fails the guard by name:

```
AssertionError: expected [ 'scene/orphanProbe.ts' ] to deeply equal []
```

Removed, 2/2 pass.

**The sweep that found them** (before the fix):

```
ORPHAN web/src/hud/LobbyPoll.tsx
ORPHAN web/src/scene/checker.ts
ORPHAN web/src/scene/enemyPalette.ts
ORPHAN web/src/shop/shopPanel.ts
```

After the fix the guard reports none, and the two that remain are allowlisted with reasons.

## Test count

342 → **333** (39 → 38 files). The count went *down* by 9: eleven tests deleted with the
dead modules, two added for the guard. A lower count with the same coverage is the point —
those eleven tests were asserting behaviour of code that could not run.

## Choice log

- **Deleted rather than kept "in case".** Both modules are superseded by working code that
  is in use, and git keeps the history. Keeping them costs every future reader a decision
  about which checkerboard is real.
- **A source-reading guard, not a bundler check.** The repo has no unused-export lint and
  adding one would mean a new dependency. The guard is 90 lines of `node:fs` and runs in
  the existing vitest pass.
- **Allowlist with reasons rather than a blanket exclusion.** `enemyPalette.ts` is
  legitimately test-only; `LobbyPoll.tsx` is a deliberate deferral. Both are different from
  "nobody wired this up", and the reason string is what distinguishes them.
- **Did not delete `LobbyPoll.tsx`.** It is the lobby variant of a mechanic that now works
  in-run (T-149). Whether the lobby should also have a vote surface is a design decision.
