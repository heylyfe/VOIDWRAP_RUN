# T-150 — no test ever opened a real vote session

**Cycle:** 22
**Status:** PASS
**Area:** `tools/vote-integration/run.mjs` (new), `justfile`, `tools/verify-live.mjs`

## What was wrong

T-149 restored the pedestal vote to the client. Nothing proved it worked end to end,
because nothing had ever opened a real vote session:

| kit | what it covers |
|---|---|
| `voting-conformance` (default) | ten checks against a **stub** server |
| `voting-conformance --real` | three shallow checks: Welcome, RunState, and a ballot rejected outside a session |
| `playthrough` | `vote` is **SKIP** — the bot never reaches level 2 |

So the only thing testing the real vote path was `VoteSession`'s own unit tests. The
mechanic could have been broken in the wiring between `open_vote_session` and the wire and
every gate would still have been green.

## The fix

A new kit, `tools/vote-integration/run.mjs`, that drives a real run with the frozen debug
manifest (`design/DEBUG_COMMANDS.md`) and then ballots:

1. connect one client (debug commands are singleplayer-only) and `Hello`;
2. `switch_level { level: 2 }` — level 1 has no vote pool;
3. loop `grant_gift { count: 255 }` until the readout says `gifts_left=0`, which puts the
   level into `LEVEL_COLLAPSE_PENDING` — the exact moment `open_vote_session` fires;
4. assert `VoteOpen` arrives with three options and a 20 s countdown;
5. send `Vote { option: N }` and assert `VoteState` counts it;
6. assert `VoteResult` names option N.

`--option` (default 1) exists so the negative test can ballot for each slot.

## Evidence

```
PASS - connect (Welcome at protocol version 8)
PASS - switch-level (switched to level 2 (seed 2096108816))
PASS - grant-gifts (gifts_left=0 after granting every normal gift)
PASS - vote-opens (VoteOpen level=2 options=3 countdown_s=20)
PASS - ballot-counted (VoteState counts=[0,1,0] seconds_left=20)
PASS - result-names-the-ballot (VoteResult winner=1 (balloted 1) id=rewind permanent=true)

vote-integration: 6/6 checks passed
```

**Negative test — the ballot decides, not the RNG.** `VoteSession::resolve` falls back to
a seeded RNG when every option ties, which is what happened before T-149. Balloting each
slot in turn produces that slot as the winner:

| `--option` | `VoteState` counts | `VoteResult` |
|---|---|---|
| 0 | `[1,0,0]` | `winner=0 id=pallbearer` |
| 1 | `[0,1,0]` | `winner=1 id=rewind` |
| 2 | `[0,0,1]` | `winner=2 id=lantern_leech` |

Three different winners from three different ballots is the proof that the ballot is what
decides.

## Gates

Added to `just verify` (self-skips without a URL, like the other live kits) and to
`tools/verify-live.mjs`, which now reports **PASS 9/9** including `vote integration`.

## Choice log

- **Drove the run with debug commands rather than making the bot finish a level.** The
  playthrough bot's `level-progression` is parked behind a balance decision (T-139) and
  re-attempting it would have been a rabbit hole. `grant_gift` reaches the same state —
  the collapse window — in one call.
- **A new kit rather than extending `voting-conformance`.** That kit's stub mode is a
  protocol conformance suite with a paired-violation selftest; adding a live-run mode would
  have muddied what it is. This kit tests one thing: a real session, end to end.
- **`--option` rather than hardcoding slot 1.** Without it the negative test is a manual
  edit, and a manual edit is not a test.
- **Read `countdown_s` / `seconds_left`, not the client's camelCase.** `wire.mjs` decodes
  the wire format, which is snake_case. The first run failed on exactly this and the
  failure was correct — it caught my own assumption, not a server bug.
