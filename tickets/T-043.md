# Ticket T-043: M2 content - classes, shop, three new enemies, level events, altar
Target: DEEPSEEK

## Context
VOIDWRAP RUN is an original fast 3D platformer: players collect gifts on floating checkerboard platforms in a misty
coloured void while enemies they voted for hunt them; golden gifts are the run's money. Tagline:
`Collect every gift. Outrun what you voted for.` All card text lives in `design/content.json`, read by the Rust
server and the TypeScript client. Tone of existing text: short, eerie, concrete; mechanics stated plainly.

## Task
Add these top-level sections to `design/content.json` (keep every existing entry byte-identical; you may add
`"behavior": "chaser"` to existing enemy params):
1. `"classes"`: exactly 4, in this order with these ids: `striker` (dash: a short burst forward), `grappler`
   (auto-aimed grapple that pulls you to the platform ahead), `blinker` (instant short teleport, 6 units, stops at
   walls), `glider` (one extra mid-air jump; hold the ability key while falling to glide). Fields: `id`, `name`
   (evocative, 1-2 words), `flavor` (one line), `ability` (one plain sentence of what the ability does),
   `controls` (e.g. "Shift / right mouse: blink toward where you move").
2. `"shop"`: 7 items bought in the lobby with golden-gift money. Fields: `id`, `name`, `flavor`, `effect` (plain,
   with numbers), `cost` (integer 5-40), `stock` (1-3 per lobby), `kind` one of `"life"` (+1 life), `"reroll"`
   (new reward cards this lobby), `"mods"` (permanent for the run, with a `mods` object using ONLY mod keys that
   existing upgrades/curses already use). Exactly one `life`, one `reroll`, five `mods` items. Balance: shop mods
   are a bit weaker than upgrades of the same cost tier; a life costs 25-35.
3. Three new `"enemies"` entries (same fields as existing ones, `threat` 1-5) with `params.behavior`:
   - `"turret"`: never moves, shoots slow glowing bolts. Extra params `fire_interval_s` (1.2-2.5) and
     `projectile_speed` (7-11); `speed` 0.
   - `"mimic"`: looks exactly like a gift until you come close, then chases. Extra param `reveal_radius` (3-4.5);
     speed between 6 and 8.
   - `"corrupter"`: slow flier that makes the platforms near it crumble. Extra param `corrupt_interval_s` (2-4);
     speed 2-4.
   `behavior` text must tell the player how to deal with it, like the existing ones.
4. `"events"`: exactly 3: `{ "id": "high_rise", "event": 1, ... }`, `{ "id": "slick_ice", "event": 2, ...,
   "friction_mul": 0.25 }`, `{ "id": "crumbling", "event": 3, ... }`, each with `name` and `banner` (one short
   line shown when the level starts, telling the player what is different).
5. `"altars"`: exactly 1: `{ "id": "bargain_altar", "name", "flavor", "effect": "Press E: gain a random upgrade AND
   a random curse. One use per altar." }` (you may reword the effect but keep the facts).
6. `tools/validate-content.mjs`: validate all new sections (ids unique and as required, numbers in the stated
   ranges, enum values, shop `mods` keys limited to keys used by existing upgrades/curses, class order).
7. `web/src/content.ts`: typed exports `CLASSES`, `SHOP`, `EVENTS`, `ALTARS` with interfaces; extend `EnemyCard.params`
   with the optional new fields; add `eventInfo(event: number)` returning the event entry or null, and extend
   `lookupCard` only if needed. TypeScript strict, no `any`, named exports.

## Constraints
Files: `design/content.json`, `tools/validate-content.mjs`, `web/src/content.ts`. Never mention or compare to any
other game, platform or brand; no emoji; JSON stays 2-space indented.

## Acceptance criteria
- [ ] `node tools/validate-content.mjs` passes and would reject a wrong class order or an unknown shop mod key.
- [ ] Existing entries unchanged; new text concrete, consistent with the mechanics above.
