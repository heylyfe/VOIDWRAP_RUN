# Ticket T-079: pedestal and voting UI (web)

Render the vote the server runs (T-078). Web only.

## What exists (verified)

- `web/src/hud/` holds the HUD panels; `JoinPanel.tsx`, `MatchList.tsx` and `matchmaker.ts` are the
  lobby browser from the previous run. Do not refactor them.
- The client speaks the generated protocol in `web/src/protocol/generated.ts`. T-078 adds `VoteOpen`,
  `VoteState`, `VoteResult` server messages and a `Vote` client message; the lead regenerates the
  TypeScript after merging T-078, so code against those names.
- The scene is react-three-fiber; the HUD is plain React over it.

## Part 1 - in-run pedestals

- Three pedestals appear near the exit during the collapse window, one per vote option.
- Each shows the option's name, its kind (enemy or curse), and a live vote count.
- A countdown ring shows the 20 s window.
- When the vote closes, a results reveal shows the winner and a "new permanent" banner naming it.
- A player who has voted sees their choice marked and can change it until the window closes.
- The pedestals must be readable at gameplay distance and must not block the beacon.

## Part 2 - lobby polls

- The same voting widget, reused as a pre-match poll any player can start.
- Options are theme and difficulty choices drawn from the pattern spec's theme vocabulary.
- Results feed the pattern engine's tag weights for the next generated level (the server owns the
  effect; the UI only reports the choice).
- Starting a poll is one button; the poll is optional and the run can start without it.

## Part 3 - tests

Vitest coverage for: rendering three options with counts, the countdown reaching zero, the results
reveal, the "new permanent" banner, a player changing their vote, the lobby poll starting and
reporting, and the empty/error states.

## Output format

Complete files with `=== FILE: <path> ===` ... `=== END FILE ===`. Allowed paths: new files under
`web/src/`, plus minimal edits to existing HUD files to mount the new components.

Do not touch `server/`, `design/`, or the matchmaker files. No new dependencies.

## Done when

`pnpm --dir web exec tsc --noEmit`, `pnpm --dir web exec eslint .` and
`pnpm --dir web exec vitest run` all pass, and the components render from mocked protocol messages.
