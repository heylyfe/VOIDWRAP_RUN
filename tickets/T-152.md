# T-152 — Silhouette distinctness, measured on rendered pixels

**Cycle:** 23
**Status:** PASS
**Area:** `web/src/scene/DevEnemyGallery.tsx` (new), `web/src/app/dev/enemies/page.dev.tsx` (new), `web/next.config.ts`, `tools/silhouette.mjs` (new)

## Why this ticket exists

Cycle 22 parked "silhouette distinctness" because the only way to measure it was to read the
model sources, and that measures the wrong thing: the models are animated JSX with
conditional rendering, refs and instanced meshes, so a source scan counts what was written,
not what is drawn. The owner's decision was to build the measurement instead of guessing:

> Build the dev-only `/dev/enemies` gallery route ... renders every enemy in a neutral scene,
> and becomes the capture source for the silhouette evidence. Rendered captures are the
> correct measurement.

So this ticket is a **measurement**, not a redesign. It ships a dev-only route, a capture
tool, and the numbers. It changes no enemy model.

## The gallery

`app/dev/enemies/page.dev.tsx` renders one enemy from `MODEL_COMPONENTS` in a dormant pose
against a flat `#101014` background, orthographic, `dpr={1}`, `antialias: false`,
`preserveDrawingBuffer: true`. `?enemy=N` picks the roster slot, `?size=R` sets the body
radius.

**Excluded from production by construction, not by a runtime check.** `next.config.ts` sets
`pageExtensions` to `["tsx", "ts"]` when `NODE_ENV === "production"` and
`["dev.tsx", "tsx", "ts"]` otherwise. A `.dev.tsx` file is therefore not a page in a release,
so the route does not exist. Verified on a real build:

```
Route (app)
┌ ○ /
├ ○ /_not-found
└ ○ /play
```

`out/dev/enemies/index.html` is absent, and `grep -rl "DevEnemyGallery\|gallery-label" out/`
returns nothing — the component is not merely unrouted, it is not in the bundle.

## Two measurement bugs found while building the tool

Both were caught by looking at the numbers rather than trusting the first green run.

**1. A head-on camera renders LURE as nothing.** The first run failed with
`FAIL - render lure (empty silhouette)`. LURE is a flat ground-plane creature — every mesh is
rotated `-Math.PI / 2` about X — so a camera at `[0, 0, 6]` sees it edge-on as a zero-height
line. The camera now sits at `[0, 2.6, 5.0]` looking at `[0, 0.35, 0]`, which is also the
projection the player actually gets: the in-game camera is above and behind.

**2. Normalising the bounding box threw away size, which is a real signal.** The first
version cropped each silhouette to its bounding box before comparing, so a 1.3-radius
Pallbearer and a 0.5-radius Mimic both became "a solid rectangle" and scored **0.948** —
a false collision. The game scales every model by its body radius
(`EnemyField` does `scale.setScalar(enemyRadius)`), and `design/content.json` carries that
radius as `params.size`, spanning 0.5 to 1.5. The gallery now applies the same scale and the
tool compares **exact pixel masks in a fixed frame**, so a size difference counts as a
difference. The normalised shape-only IoU is still computed, as a diagnostic.

## The numbers

20 enemies at gameplay body radius, 512x512 fixed frame, 190 pairs:

```
distribution over 190 pairs: min 0.000  p25 0.129  median 0.245  p75 0.339  p90 0.432  max 0.780
```

Closest pairs (fixed-frame IoU, shape-only in brackets):

| pair | IoU | shape-only |
|---|---|---|
| peal / coil | 0.780 | 0.754 |
| peal / blight | 0.737 | 0.858 |
| warden / peal | 0.674 | 0.807 |
| warden / blight | 0.660 | 0.793 |
| pallbearer / peal | 0.621 | 0.600 |

The roster is well spread: the median pair shares a quarter of its footprint, and the worst
pair is far above p90 rather than part of a cluster. `peal`/`coil` is the tightest pair —
both are roundish zone enemies of similar radius — and it is within tolerance, because a
player separates them by accent colour and telegraph, not by outline alone.

## The thresholds, and why they are these numbers

`MAX_IOU = 0.82` is a **regression guard, not a perceptual constant**. There is no standard
for "these two shapes are the same creature", so the number is anchored to the shipped
roster: the worst pair today is 0.780 and p90 is 0.432, so 0.82 leaves the current roster
passing with headroom while still failing any new model more alike than anything already
shipped. A pair above it is not automatically wrong — it is a pair that has to be justified.

`MIN_FILL = 0.08` is measured on the **normalised shape**, not the frame. The first version
tested frame fill, which failed 13 of 20 enemies for being small — it was measuring size, not
thinness, and size is already carried by the fixed-frame IoU. On the normalised shape the
thinnest is `kite` at 0.129, so the gate asks the question it means to ask: is the outline a
hairline that reads as nothing.

`silhouette-framing` is a third check: a silhouette touching the frame edge is a framing
failure, not a shape. 0 clipped.

## Negative test

A threshold that has never been seen to reject anything is not a check. `--selftest` feeds
the same comparison functions known-answer masks:

```
PASS - selftest.identical masks score 1.0 (got 1, want 1)
PASS - selftest.identical masks exceed MAX_IOU (got 1, want > 0.82)
PASS - selftest.disjoint masks score 0.0 (got 0, want 0)
PASS - selftest.half-overlapping boxes score 1/3 (got 0.3333333333333333, want 0.3333333333333333)
PASS - selftest.hairline shape is under MIN_FILL (got 0.015625, want < 0.08)
PASS - selftest.bit and mask IoU agree (got 0.3333333333333333, want 0.3333333333333333)

silhouette selftest: PASS (6/6)
```

## Result

```
PASS - silhouette-overlap (closest pair peal/coil at 0.780; threshold <= 0.82)
PASS - silhouette-fill (thinnest 0.129; threshold >= 0.08)
PASS - silhouette-framing (0 clipped)

silhouette: PASS
```

## Choices made

- **The gallery reads `size` from the URL rather than importing content.** The tool reads
  `design/content.json` and passes `params.size` in the query string, so the body radius has
  one source of truth and no generated constant to drift.
- **The silhouette is computed in the browser.** `page.evaluate` draws the WebGL canvas to a
  2D canvas and reads the pixels, so the tool needs no PNG decoder and no new dependency.
- **The mask crosses the JSON boundary packed and base64-encoded** (32 KB per enemy), so the
  fixed-frame IoU is exact rather than sampled on a grid.
- **`tools/silhouette.mjs` self-skips with exit 0 when no URL is given**, so `just verify`
  stays green without a dev server. It is not wired into `just verify` for that reason; it is
  a capture tool, run deliberately.
- **No enemy model was changed.** The audit passes on the roster as shipped; the ticket's job
  was to make the question answerable.
