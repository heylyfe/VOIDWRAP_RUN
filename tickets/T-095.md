## The measured defect

`node tools/pattern-audit/run.mjs --from tools/economy-audit/levels.ndjson` over
3,000 generated levels reports:

```
FAIL - 2.tag-diversity.mechs (vocabulary coverage 9/10 values used (never offered: dead_end))
```

`mech:dead_end` is not missing from the data. `design/patterns-a.json` carries three
patterns with `"mech:dead_end"` and `"role": "dead_end"`, and `design/chunks.json`
carries it on ch16/ch17/ch18. The engine simply never selects one.

**Root cause, exact:** `server/crates/sim/src/pattern.rs:665` builds the walk pool as

```rust
.filter(|&i| matches!(metas[i].role, ChunkRole::Path | ChunkRole::Junction) && metas[i].min_level <= level)
```

`ChunkRole::DeadEnd` is not in that list, so a dead-end pattern can never enter the
pool, and `allowed_after`'s dead-end rule at line 807 is unreachable code.

## The fix (conservative, additive)

A dead-end pattern has no exit socket, so it cannot sit in the middle of a linear
plan. It can only **terminate** one. So:

1. Keep the walk pool as it is for positions `0..len-1`.
2. For the **final** position only, allow `ChunkRole::DeadEnd` as well — a terminal
   flourish at the end of the plan.
3. Give it a modest weight so it appears sometimes, not always: a dead-end candidate
   is eligible for the last slot with probability `DEAD_END_CHANCE` (a named
   `const`, start at `0.25`), decided from the plan's own seeded RNG so the same seed
   always produces the same plan.
4. If the last slot picks a dead-end, the plan is one element shorter in walk terms —
   that is fine, `plan.len()` is unchanged because the dead-end occupies the slot.
5. Never place a dead-end at position 0 (the hub) or anywhere before the last slot.

Do not change `allowed_after`, `theme_run`, `plan_len`, `tier_for`, the bag, or the
hub selection. Do not touch `design/` at all. Do not touch `levelgen.rs` unless a
compile error forces it, and say so in the notes if it does.

## Tests (required, in `pattern.rs`'s existing `mod tests`)

1. `a_dead_end_can_terminate_a_plan` — build plans across at least 64 seeds with a
   catalog that contains dead-end patterns; assert at least one plan ends on a
   dead-end and that no plan has a dead-end anywhere but the last index.
2. `a_dead_end_never_appears_mid_plan` — over the same sweep, assert every dead-end
   index equals `plan.len() - 1`.
3. `the_same_seed_still_reproduces` — the same seed, level, players and tier produce
   an identical plan across two builds (the dead-end decision must be seeded, not
   random).
4. `a_catalog_without_dead_ends_is_unchanged` — a catalog with no dead-end patterns
   produces exactly the plans it produced before this change (compare against a
   plan built with `DEAD_END_CHANCE` effectively zero, or assert no dead-end appears
   and the length is unchanged).
5. `dead_end_chance_is_respected` — over 512 seeds, the fraction of plans ending on a
   dead-end is within `0.10..0.45` (a loose band around 0.25, so the test is not
   flaky).
