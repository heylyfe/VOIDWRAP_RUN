# T-108 — Shop prices scale with income per level

**Agent:** model:acpRegistry_mistral_vibe/deepseek-v4 (fresh thread)
**Owns:** shop pricing data + tests.

## Problem
Shop prices are flat while income grows with level, so the shop stops mattering
in long runs.

## Measured baseline (economy audit, 400 seeds)
- gifts per level: median 183, mean 191.78, min 72, max 434
- cheapest shop item: 200 currency
- levels of income to afford the cheapest item: **1.09**
- static pool: 7 (life/reroll/mods), 4 offered per shop
- upgrade draws: 2 at 300 each; perks 4; radar 3; counters 20
- items per shop before counters: 13
- shop opens on level 1: standard/extreme/random no, chaos yes

So a player clears the cheapest item in about one level at level 1 and the gap
only widens. The audit's `1.gift_income` line passes, but it measures income, not
whether the shop keeps pace.

## Work
1. Derive expected income per level bracket from the measured curve (gift count
   per level, level rewards, streak/achievement income). Put the derivation in
   the ticket with numbers.
2. Make shop prices a function of level bracket: early brackets cheap, later
   brackets scaled to income so the shop stays meaningful. Data-driven — one
   file, so later balancing is a data edit.
3. Unit-test the price curve against the income curve: no bracket where the
   player trivially buys everything, and no dead stock (an item that is never
   worth buying at any bracket).
4. Re-run the economy audit and add a metric line that asserts the price/income
   ratio stays inside a band across brackets.

## Done when
Price-per-bracket curve implemented and tested against income data; economy
audit re-run confirms the shop tracks the curve; gates green.

## Autonomous choices
- Scaling by **bracket**, not by exact level: brackets keep the curve legible
  and avoid a price table with 50 rows.
- Balancing stays deferred per the standing order: this ticket makes the curve
  *track* income, it does not tune the game's difficulty.
