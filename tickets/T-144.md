# T-144 — Empty denominators: a metric with nothing to measure must not report PASS

**Cycle:** 19 · **Agent:** orchestrator (deepseek-v4) · **Status:** PASS

## Why

A worker review of both audit tools asked one question: *is any threshold looser than
the metric's stated intent?* It found a whole defect class, not a single bug.

Every rate metric in `tools/pattern-audit/run.mjs` is written as

```js
const rate = denom ? viol / denom : 0;
line(name, rate <= MAX, ...);
```

When `denom` is 0 the rate becomes 0, and `0 <= MAX` is true, so the metric reports
**PASS** having measured nothing. That is the same defect as T-134's
`6.enemy-frequencies.never-offered` ("a check that could never fail"), which was fixed
for one metric and left in place for eleven others.

This is the project's second recurring defect class — *a threshold looser than the
metric's stated intent* — found in T-126, T-127, T-133, T-134, T-137 and now here. The
first class is *the piece exists but never reaches a level/player*. Both are silent.

## The distinction that makes the fix honest

`Number(rec.gifts ?? 0)` makes an **absent dump field** indistinguishable from a
**measured zero**. Those two cases need opposite responses:

| case | meaning | correct verdict |
|---|---|---|
| field absent from every record | the dump cannot answer this question | **SKIP**, naming the field |
| field present, total is zero | the game genuinely has no gifts/ramps | **FAIL** |
| field present, denominator zero for a structural reason | nothing of that shape was generated | **SKIP**, naming the reason |

So the fix tracks field presence separately from field value, and every metric that can
divide by zero now routes to one of the three rows above instead of falling through to
PASS.

## Changes — `tools/pattern-audit/run.mjs`

1. **`tallyField`** — new helper recording, per dump field, how many records actually
   carried it. Called for `gifts`, `ramps`, `unreachable_gifts`, `fallbacks`.
2. **`7.catalog-coverage`** — the unreadable-`design/` path called
   `line(name, true, 'SKIP: ...')`, i.e. it emitted a **PASS line whose text began with
   "SKIP"**. It now calls the real `skip()` helper. This was historical defect #4
   verbatim, on the metric that was created to catch T-132.
3. **`5.ramp-anchors`** — `rampAnchors === 0` → SKIP (field absent) or FAIL (field
   present, zero ramps).
4. **`5.reachability`** — `gifts === 0` → SKIP/FAIL as above.
5. **`5.gift-spawn-safety`** — same; the dead `gRate` local is now used in the message.
6. **`5.heights`** — `heightPairs === 0` → SKIP.
7. **`5.ramps`** — `rampChecked === 0` → SKIP.
8. **`5.stairs`** — `stairPatterns.size === 0` → SKIP.
9. **`1.pattern-repeat.across-seeds`** — vacuous with one seed; requires
   `seedsSeen.size >= 2`.
10. **`6.enemy-frequencies.always-offered`** — a cell qualified only if
    `cell.byType.size >= 2`, so a single type appearing in 100% of levels was filtered
    out of the check designed to catch exactly that. Filter dropped. The whole metric-6
    family now SKIPs when the dump carries no `enemies` array.
11. **`3.anchor-fallbacks`** — a missing `fallbacks` field was indistinguishable from
    zero fallbacks; now SKIPs when no record carried the field.
12. **`2.tag-diversity.themes` / `.mechs`** — mean/min were computed over
    `entry.themes.size`, which includes unknown forward-compat tags, so an unknown tag
    inflated the diversity score while vocabulary coverage passed at a 0.02% share.
    Mean/min now count **vocabulary tags only**; unknown values stay reported.
13. **RESULT line** — now prints the skipped count, so a SKIP can never be mistaken for
    coverage in a log skim.

## Changes — `tools/economy-audit/run.mjs`

14. **`8.hazard_entities`** — `if (tagged.length > 0 && ...)` meant a hazard tag with
    **zero** tagged patterns passed. A tag that no pattern carries is the strongest
    possible form of "a promise the engine does not keep", so it now fails.
15. **`6.radar_offering`** — `radar.length === 3` did not check the ids were distinct;
    three copies of one module would pass. Now asserts `new Set(ids).size === 3`.
16. **`2.shop_offer_mix`** — `perShop` used `SHOP_OFFER` rather than
    `Math.min(SHOP_OFFER, statics.length)`, so the printed number overstated the real
    offer, and the `>= 4` floor was dead code (the expression is structurally >= 6).
    Now uses the real offer and asserts the floor against it.

## Result

Real dump (400 seeds, 6,000 level records): **17 lines, 0 failed, 1 skipped** — unchanged
from before, because the real dump carries every field and the game has gifts, ramps and
height pairs. The fix changes what happens when the input is *not* healthy, which is the
point.

`--selftest` still reports exactly the six planted failures.

## Choice log

- **SKIP vs FAIL for a zero denominator.** Chose per-case rather than uniformly. A
  uniform FAIL would fire on the synthetic selftest fixtures and on any partial dump,
  training readers to ignore it; a uniform SKIP would let a real "gifts stopped
  generating" regression pass silently. Field presence is the discriminator that makes
  the two cases separable, so it is measured rather than guessed.
- **Did not add a `--strict` flag** that turns SKIP into FAIL. The gate already reads
  the RESULT line; adding a second mode doubles the surface for the same information.
  The skipped count in the RESULT line is the visibility fix.
- **Left `5.reference-scale` alone.** Its `sRate = placed ? viol / placed : 1` already
  fails on an empty denominator — it is the pattern the other metric-5 lines now copy.

## Found while implementing: the selftest had been failing unnoticed

`node tools/pattern-audit/run.mjs --selftest` was reporting **FAIL** on `main` before this
ticket touched anything. `7.catalog-coverage` fails on the synthetic records because their
ids (`p1_0`, `p2_3`, ...) are deliberately not in the real catalog, and the selftest's
expected-failure set never learned about that metric. Nothing gated `--selftest`, so it
rotted silently — the same "a check nobody runs is not a check" shape as the rest of this
ticket.

Two fixes:

1. **`report()` takes an injectable catalog** (`ctx.catalogIds ?? CATALOG_IDS`), so the
   selftest supplies a synthetic one and `7.catalog-coverage` measures the metric instead
   of tripping over it.
2. **`--selftest` is now part of `just verify`**, immediately after `validate-content`.
   Its report lines are prefixed `[selftest]` so the six planted FAILs cannot be mistaken
   for a real audit failure in the gate log.

## Found while implementing: `5.stairs` needed a real denominator

The first version of the guard used `geo.stairPatterns.size === 0`, which is wrong:
`stairPatterns` only gains an entry when a chain is **found**, so it cannot distinguish
"no stairs exist" (the desired state) from "nothing was checked". On the real dump that
made `5.stairs` SKIP when it should PASS. Added `geo.multiBoxPatterns`, incremented for
every pattern with 2+ boxes — the actual population the stair detector runs over. Real
dump: `0 stair sequences across 210,000 multi-box patterns` → PASS.
