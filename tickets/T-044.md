# Ticket T-044: Desktop app window, in-game hosting for friends (LAN + internet via UPnP)
Target: INKLING (max effort)

## Context
VOIDWRAP RUN ships as one program, `voidwrap-server(.exe)`: an axum server that runs the authoritative game, serves
the static web client from a `web/` folder next to it, and (with VOIDWRAP_OPEN_BROWSER) opens the system browser.
The human wants the final product to be real desktop software, not a website, and wants multiplayer hosted from a
player's own computer: one player hosts, friends join - on the same network and over the internet.

Crates you MAY add (exact versions verified to exist): `wry = "0.57"`, `tao = "0.37"` (both only behind a new cargo
feature `desktop`, `optional = true`), `igd-next = { version = "0.18", features = ["aio_tokio"] }` (always on).
Use only APIs you are certain exist in those versions; keep their use small and isolated so the lead can fix a
signature quickly. Note uncertain calls in NOTES.

## Task
1. Desktop window (feature `desktop`): new module `desktop.rs`. When the binary is built with `--features desktop`
   and not started with `--browser` or `--headless` and `PORT` is not set: run the existing server on a tokio
   runtime in a background thread, wait until it accepts connections (or 10 s), then open a native window
   (tao event loop on the MAIN thread, wry WebView) titled "VOIDWRAP RUN", 1280x800, resizable, loading
   `http://localhost:<port>/`. Closing the window shuts the server down (best effort) and exits. Without the feature
   (Linux CI, servers) behaviour is exactly as today. On Windows with the feature, hide the console
   (`#![cfg_attr(all(windows, feature = "desktop"), windows_subsystem = "windows")]`) but keep logging to a file
   `voidwrap.log` next to the exe so problems can be reported.
2. Hosting for friends, started from inside the game (no separate launcher): new module `host.rs` and HTTP routes
   in `net.rs`:
   - `GET /api/host` -> JSON `{ "hosting": bool, "port": u16, "lan": ["192.168.1.23", ...], "public": "203.0.113.5"
     | null, "upnp": "off" | "trying" | "open" | "failed", "message": string }`.
   - `POST /api/host` with JSON `{ "enable": bool }` -> starts/stops hosting and returns the same JSON.
   - Both routes refuse (403) requests whose peer address is not loopback (use axum `ConnectInfo<SocketAddr>`;
     serve with `into_make_service_with_connect_info::<SocketAddr>()`). Friends must never be able to toggle hosting.
   - Hosting = an extra listener on `0.0.0.0:<HOST_PORT>` (default 7879, env `VOIDWRAP_HOST_PORT`) serving the same
     router and the same game, while the normal 127.0.0.1 listener keeps working. Stopping hosting closes it (use a
     shutdown signal / abort handle). If `VOIDWRAP_HOST=0.0.0.0` is set at start (old launcher), keep today's
     behaviour and report `hosting: true`.
   - When hosting starts, try UPnP in the background with igd-next (search gateway with a 3 s timeout, map TCP
     HOST_PORT -> this machine's LAN address for 2 hours with description "VOIDWRAP RUN", read the external IP).
     Remove the mapping when hosting stops or the program exits (best effort, short timeout). Report status in
     `upnp`/`message` in plain words a non-technical player understands (for example "Friends anywhere can join
     with the address below." or "Your router did not allow automatic setup. Friends on your Wi-Fi can still join;
     for internet play see HOW-TO-PLAY.md.").
   - LAN addresses: list this machine's private IPv4 addresses without new crates (the classic trick: a UDP socket
     `connect`ed to 8.8.8.8:80 reveals the outbound local address; no packet is sent). At least that one address.
3. Keep `--browser` working (today's behaviour: print the address, open the system browser when
   VOIDWRAP_OPEN_BROWSER is set). Print the hosting status to the log/console too.
4. Tests (no network in tests): the JSON shape of host status, loopback-only check (unit-test the peer filter
   function), host port parsing, status messages. Keep all existing server tests passing.

## Constraints
Files: `server/crates/server/Cargo.toml`, `server/crates/server/src/main.rs`, `server/crates/server/src/net.rs`,
`server/crates/server/src/desktop.rs` (new), `server/crates/server/src/host.rs` (new). Do NOT touch `game.rs`,
`run.rs`, `content.rs` (other tickets change them now). No secrets, no telemetry, no outbound traffic except the
UPnP gateway on the local network.
