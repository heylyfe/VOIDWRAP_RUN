# Ticket T-087: hazards - trampolines and tripmines

Two hazard families as PATTERN TAG elements for the composition engine. Implemented in the shared sim
crate so server and WASM prediction agree.

## The hazards

1. **Trampoline**: a high-bounce pad. Different arcs and different routing than a jump pad - it throws
   the player much higher and further, so it opens vertical routes a jump pad cannot.
2. **Tripmine**: an armable ground hazard with a visible telegraph. It disarms briefly after
   triggering, so a route reopens behind the player who set it off.

## Requirements

- Both live in `server/crates/sim/src/hazards.rs` alongside the existing hazards, with the same
  determinism rules (no wall clock, no transcendentals in the step path).
- The pattern format gains the `trampoline` and `tripmine` hazard tags (they are already reserved in
  `design/PATTERN_FORMAT.md`); the harness must validate tagged patterns.
- Both appear as pedestal curse options ("more trampolines", "minefield") with frequency tags that
  EXTREME and CHAOS modes raise.
- Tests: a trampoline launch reaches its documented height, a tripmine triggers once and re-arms after
  its cooldown, and a tagged pattern validates.
- Doc-comment every public item.

## Output format

Complete files with `=== FILE: <path> ===` ... `=== END FILE ===`, or single functions with
`=== FN: <path> :: <name> ===` ... `=== END FN ===`. Allowed paths: `server/crates/sim/src/`,
`server/crates/server/src/`, `design/PATTERN_FORMAT.md`, `design/patterns-a.json`,
`design/patterns-b.json`.

Do not touch `web/` or `protocol/` unless a client-visible field is genuinely required; if it is,
change `protocol/schema.json` and note that the lead must run `just gen` and `just fixtures`.

## Done when

`cargo test -p sim` and `cargo test -p server` pass, clippy is clean, and the harness validates tagged
patterns. Put the launch and cooldown numbers in NOTES.
