# Ticket T-049: App icon, Windows installer, exe metadata
Target: INKLING (max effort)

## Context
VOIDWRAP RUN ships on Windows as `VOIDWRAP RUN.exe` (a Rust program: game server + native window via tao/wry,
behind the cargo feature `desktop`) next to a `web/` folder, zipped by `tools/package.mjs` and published by a GitHub
Actions release workflow. The human wants real software: a proper app icon and an installer.

Art direction (the icon must be ORIGINAL - no resemblance to any existing game's logo): a misty coloured void
(deep violet-black `#07060d` to `#1a0f2e`), a glowing gift box seen at a 3/4 angle with a magenta `#ff3db8` ribbon,
sitting on a small floating checkerboard tile (dark + violet `#5a2a8c` squares) with a thin cyan `#38e8ff` rim
light; a faint ring/portal glow behind it. Bold silhouette that still reads at 16x16 (simplify: at small sizes the
gift + ribbon is enough). Rounded-square background is fine.

## Task
1. `design/icon/icon.svg`: the icon as a hand-written SVG, viewBox 0 0 256 256, no external references, no text,
   gradients/filters allowed (they must render in Chromium). Also `design/icon/icon-small.svg` (viewBox 0 0 32 32),
   a simplified version used for the 16/24/32 px sizes.
2. `tools/make-icon.mjs` (Node 24+, ESM, no new npm packages; Playwright is available exactly the way
   `tools/capture.mjs` loads it via `createRequire(web/package.json)` and `require("@playwright/test")`):
   render the SVGs with headless Chromium to transparent PNGs at 16, 24, 32 (small SVG) and 48, 64, 128, 256 (big
   SVG); write `design/icon/icon.ico` (a valid ICO containing all seven sizes as PNG-compressed entries - write the
   ICONDIR/ICONDIRENTRY headers yourself), `design/icon/icon-256.png`, `web/public/icon.png` (256), and
   `design/icon/icon-64.rgba` (raw 64x64 RGBA8 bytes, 16384 bytes, for the native window icon; get pixels via a
   canvas `getImageData` inside the page). Deterministic output. Print what it wrote.
3. Window icon: in `desktop.rs`, set the tao window icon from `include_bytes!` of `design/icon/icon-64.rgba`
   (path relative to the crate: `../../../../design/icon/icon-64.rgba`) using `tao::window::Icon::from_rgba(bytes,
   64, 64)` and `WindowBuilder::with_window_icon`; failure to build the icon only logs a warning.
4. Exe icon + metadata: `server/crates/server/build.rs` that, only when the target OS is Windows
   (`std::env::var("CARGO_CFG_TARGET_OS") == Ok("windows")`), uses the `winresource` crate (add as
   `[target.'cfg(windows)'.build-dependencies] winresource = "0.1"`) to embed `design/icon/icon.ico` and set
   ProductName "VOIDWRAP RUN", FileDescription "VOIDWRAP RUN", CompanyName "VOIDWRAP RUN", LegalCopyright
   "VOIDWRAP RUN contributors", OriginalFilename "VOIDWRAP RUN.exe", versions from `CARGO_PKG_VERSION`. Emit
   `cargo:rerun-if-changed` for the ico. Build must still succeed on Linux and without the desktop feature.
5. Installer: `release/installer.nsi` (NSIS 3, Modern UI 2, Unicode true):
   - Installs PER USER without admin rights (`RequestExecutionLevel user`) into
     `$LOCALAPPDATA\Programs\VOIDWRAP RUN`; the source folder is passed as `/DSRC=<folder>` and the version as
     `/DVERSION=<x.y.z-tag>`; output file name passed as `/DOUTFILE=<path>`.
   - Copies everything from SRC (the packaged folder: `VOIDWRAP RUN.exe`, `web\` recursively, `PLAY-IN-BROWSER.cmd`,
     `HOW-TO-PLAY.md`, `ENEMIES.md` if present).
   - Start Menu shortcut "VOIDWRAP RUN" and a Desktop shortcut (a checkbox on the components page, checked by
     default), both with the app icon; a "How to play" Start Menu entry opening HOW-TO-PLAY.md.
   - Pages: Welcome, Directory, Components (Desktop shortcut), Install, Finish with "Start VOIDWRAP RUN now".
   - Uninstaller registered under HKCU `Software\Microsoft\Windows\CurrentVersion\Uninstall\VOIDWRAP RUN`
     (DisplayName, DisplayIcon, DisplayVersion, Publisher "VOIDWRAP RUN", UninstallString, InstallLocation,
     NoModify, NoRepair, EstimatedSize); the uninstaller removes the files, shortcuts and key, and keeps nothing.
   - Installer and uninstaller use `design/icon/icon.ico` (path relative to the .nsi: `..\design\icon\icon.ico`).
   - If the game is running during install/uninstall, ask the user to close it (simple message box loop using
     `FindWindow` on the window title "VOIDWRAP RUN" is enough).
   - Plain friendly wording for non-technical players. No mention of any other game, platform or brand except
     Windows.
6. `tools/package.mjs`: after packaging on Windows with the desktop build, if `makensis` is available (on PATH or at
   `C:\Program Files (x86)\NSIS\makensis.exe`), build `dist/VOIDWRAP_RUN-<version>-windows-setup.exe` where
   `<version>` comes from env `VOIDWRAP_VERSION` (default "dev"); otherwise print a clear note and continue. Also copy
   `ENEMIES.md` into the package when it exists in the repo root.
7. `.github/workflows/release.yml`: on the Windows job, run `node tools/make-icon.mjs` is NOT needed (icons are
   committed); ensure NSIS exists (`if (-not (Get-Command makensis -ErrorAction SilentlyContinue)) { choco install
   nsis -y }` and add `C:\Program Files (x86)\NSIS` to PATH), set `VOIDWRAP_VERSION` to the tag name, and upload the
   setup exe as an additional release asset next to the zip.

- [ ] `cargo clippy --workspace --all-targets -- -D warnings` passes with and without `--features desktop`.
- [ ] The NSIS script compiles with makensis 3 and installs/uninstalls cleanly per user.
- [ ] NOTES: every NSIS macro/plugin used (only standard NSIS ones), and anything uncertain.
