# Ticket T-082: the between-level shop

A shop floor between levels where gift-derived currency buys upgrades, curse removals and class perks.
Server-authoritative. Reuse the existing M3 upgrade/curse systems; do not replace them.

## What exists (verified)

- `server/crates/server/src/run.rs` owns `Run` (level, phase, mods, currency) and already has a shop
  concept: `ShopOffer`, `ShopPurchase`, `ShopError`, `valid_picks`, and a `Buy` client message.
- `design/content.json` has `shop`, `upgrades`, `curses`, `classes` and `grades` sections.
- `design/ENEMY_REGISTRY.md` defines the permanents a run accumulates.

## Requirements

- A shop floor between levels: the run pauses on it, players spend currency, then continue.
- Offerings: upgrades (existing mod cards), curse removals (pay to drop a curse), class perks, and
  counters to specific permanents the run has accumulated (read the registry: an enemy's counter is
  sold as an item that helps against it).
- Server-authoritative: the server validates every purchase, owns the currency, and rejects races.
  Two clients racing for the last copy of an item: exactly one wins, the other gets a clear error.
- Currency math unit-tested: earning, spending, insufficient funds, refunds on a rejected purchase.
- The shop must not break the existing draft flow or the existing `Buy` message; extend rather than
  replace.
- UI: vitest coverage for the shop panel (offers render, buy succeeds, buy fails, sold-out state).

## Output format

Complete files with `=== FILE: <path> ===` ... `=== END FILE ===`, or single functions with
`=== FN: <path> :: <name> ===` ... `=== END FN ===`. Allowed paths: `server/crates/server/src/`,
`server/crates/sim/src/` (shared types only), `design/content.json`, `web/src/`.

Do not touch `protocol/` unless a new message is genuinely required; if it is, change
`protocol/schema.json` and note that the lead must run `just gen` and `just fixtures`. No new deps.

## Done when

`cargo test -p server` and the web suite pass, clippy is clean, and the race test proves exactly one
winner. Put the price and income numbers you chose in NOTES - balancing comes later.
