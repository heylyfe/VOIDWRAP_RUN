## Context
VOIDWRAP RUN's authoritative server (`server/crates/server`): a game actor (`game.rs`) owns connections and a `Run`
(`run.rs`); card/content data comes from `design/content.json` (`content.rs`). The run flow is: lobby (draft screen;
level 1 is a plain round with no cards) -> generated level -> gifts -> golden gifts + beacon -> lobby -> ...
M2 pieces already exist and are tested in the `sim` crate (you wrote most of them):
- `sim::controller`: `ControllerState.class` (CLASS_STRIKER/GRAPPLER/BLINKER/GLIDER) picks the ability;
  `Tuning.friction_mul` (ice); `World::set_tiles(&[TileState])` makes TILE_GONE platforms non-solid.
- `sim::hazards::Hazards` (turret projectiles, mimic, corrupter, crumbling tiles) and `sim::rules` behaviours.
- `sim::levelgen::generate` now returns levels with `event` (EVENT_*), `altars`, and PLATFORM_CRUMBLE platforms.
- `design/content.json` now has `classes`, `shop`, `events`, `altars`, and enemies with `params.behavior`
  ("chaser" | "turret" | "mimic" | "corrupter") plus `fire_interval_s`, `projectile_speed`, `reveal_radius`,
  `corrupt_interval_s`.
- The web client already sends `ClientMsg::Buy { item }` / `ClientMsg::ChooseClass { class }` and handles
  `ServerMsg::Shop`, `ServerMsg::Notice`, and Snapshot `projectiles` / `tiles` / `altars_used`, `EnemyView.state`.

## Task
1. Content (`content.rs`): parse the new sections (classes, shop, events, altars; serde with defaults so older
   fields still load). Map enemy `behavior` strings and second-based params to `EnemyParams` (ticks = seconds x
   TICK_HZ, rounded, minimum 1). Unknown behavior -> chaser. Keep curses applying (speed/aggro/size/grace muls).
2. Hazards (`run.rs`/`game.rs`): replace the per-enemy `rules::step_enemy` loop with one `Hazards` per run, reset on
   every new level; after each `Hazards::step`, call `world.set_tiles(&hazards.tiles())` so crumbled platforms stop
   being solid for every player's controller. Deaths use `Hazards::hit` (DEATH_ENEMY / DEATH_PROJECTILE) plus the
   void check; dormant and disguised enemies stay harmless. Snapshot fills `projectiles`, `tiles`, `altars_used`,
   and `EnemyView.state` via `enemy_state`. The `RunSummary.cause` can now be DEATH_PROJECTILE. Mimic enemies spawn
   at a gift-like spot: use one of the generated `enemy_spawns` but move it down onto the platform top (pos.y =
   top + 0.5) - keep it simple and document the choice.
3. Classes: each player has a class (default CLASS_STRIKER). `ChooseClass` is accepted only in the lobby
   (PHASE_ENEMY_DRAFT) while the run is on level 1 (the first lobby); otherwise reply with the existing error path
   (code 409, plain message). Values > CLASS_GLIDER -> 400. The class is copied into the player's
   `ControllerState.class` at every spawn/respawn and survives respawns and new levels; a new run keeps the
   player's last class (they can change it in the next first lobby). `PlayerView.class` reports it.
4. Level events: `Tuning.friction_mul` = the event's `friction_mul` from content for EVENT_ICE levels, else 1.0;
   `RunInfo.tuning` carries it (the client predictor reads it). At level start broadcast
   `Notice { kind: NOTICE_EVENT, ids: [event id] }` when the level has an event.
5. Shop: in every lobby from level 2 on (not the first, plain lobby), offer 4 shop items picked with the run RNG
   (stock from content), sent as `ServerMsg::Shop` together with the Draft (and re-sent after every purchase so all
   players see stock/currency). `Buy { item }`: only in the lobby, item must be in the current offer with stock > 0
   and `currency >= cost` (currency is team-wide, as today); then subtract, decrement stock, apply: "life" -> +1
   life; "reroll" -> replace the REWARD cards of the current draft offer (keep enemy cards; clear existing reward
   votes from all players and re-send the Draft to everyone, marking it fresh); "mods" -> apply like an upgrade
   (record the item id in `RunInfo.upgrades`? NO - keep RunInfo lists for cards; just apply mods). Broadcast
   `Notice { kind: NOTICE_BOUGHT, ids: [item id] }` and a fresh RunState. Errors: 409 not in lobby / sold out,
   402 not enough money, 404 unknown item; never kick.
6. Altars: during PHASE_PLAYING, an ACTIVE player pressing BTN_INTERACT (rising edge, from their input frames)
   within 2.0 units horizontally and 1.5 vertically of an unused altar uses it: one random upgrade and one random
   (non-greater) curse are applied (run RNG; add their ids to RunInfo upgrades/curses lists), the altar id is added
   to `altars_used`, then broadcast `Notice { kind: NOTICE_ALTAR, ids: [upgrade id, curse id] }` and a RunState.
   One use per altar per level.
7. Keep everything that exists working: multiplayer spectating, votes, lives, golden gifts, the plain first round.
   Update existing tests only where M2 changes behaviour, and add tests for: content mapping (seconds to ticks,
   behaviors), class choice rules and persistence across respawn, ice friction in RunInfo, event notice, shop
   offer/buy/errors/reroll, altar use and one-use limit, projectile death cause, tiles in snapshots after crumbling
   (drive a player onto a PLATFORM_CRUMBLE platform in a constructed level).
