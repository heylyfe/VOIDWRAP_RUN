# Ticket T-076: enemy model and visual polish

A procedural polish pass over EVERY enemy, old and new. Existing pipeline only: no binary assets, no
new dependencies, no external models.

## What exists (verified)

- Enemies are drawn by the client from `EnemyView` (position, radius, behaviour, phase).
- `web/src/scene/` holds the rendering; `design/VISUAL_DIRECTION.md` is the art direction.
- The registry (`design/ENEMY_REGISTRY.md`) gives each enemy a cue tier, which obliges a visible
  telegraph.

## Requirements

- Every enemy gets a distinct, readable silhouette: at gameplay distance you can tell a Rewind from a
  Lure from a Coil without reading a label.
- Every telegraph is visible: tier 1 under 1 s must read as a flash, tier 2 as a wind-up, tier 3 as an
  ambient state. The Lure's fog pulse and the Static's near-invisibility are part of this.
- Motion feel: each enemy's movement should read as its identity (Rewind replays, Coil leaps, Warden
  patrols, Kite tracks).
- Keep the existing palette and fog treatment; do not restyle the whole game.
- Evidence: run `just capture` and attach the screenshots to the ticket response. If the headless
  renderer cannot reach a playable frame rate in this environment, say so and attach what it produced.

## Output format

Complete files with `=== FILE: <path> ===` ... `=== END FILE ===`. Allowed paths: `web/src/`.

Do not touch `server/`, `design/`, or `protocol/`. No new dependencies.

## Done when

`pnpm --dir web exec tsc --noEmit`, `pnpm --dir web exec eslint .` and
`pnpm --dir web exec vitest run` pass, every enemy has a distinct silhouette and a visible telegraph,
and screenshots are attached. List each enemy and what you changed in NOTES.
