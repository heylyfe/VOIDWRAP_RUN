# Ticket T-086: radar and HUD modules

Purchasable radar modules sold in the shop (T-082). Each is an upgrade item with a clear counter-value
against specific registry enemies.

## The modules

1. **Gift arrow** (`radar_gift_arrow`): a compass arrow to the nearest uncollected gift, with distance.
   Counters `lure` (the fog decoy that reads as a gift) and `static` (nearly invisible in fog).
2. **Enemy radar** (`radar_enemy`): pings the positions of the run's permanents on a cooldown - a short
   pulse, not a permanent wallhack. Counters `static`, `overlook` and `kite`.
3. **Ground-hazard radar** (`radar_hazard`): shows tripmines and trampolines within a radius. Those
   hazards land in T-087, so this module ships with the radius and the query and is wired to real
   hazards when T-087 merges. Counters `coil` and `lure`.

## What exists (verified against the tree)

- `design/content.json` has a `shop` array; `ShopItemDef` is `{id, cost, stock, kind, mods}` and the
  known kinds are `"life" | "reroll" | "mods" | "counter" | "perk"` (content.rs:154, enforced at
  content.rs:310 and by `SHOP_KINDS` in tools/validate-content.mjs:177).
- `Run` owns the shop (`pub shop: Option<Vec<ShopOffer>>`) and `buy` applies an item.
- `web/src/hud/GameHud.tsx` is the in-run HUD: a level badge, a beacon banner and the gift counter.
  It takes plain props and renders with Tailwind classes; it has no server connection of its own.

## Part 1 - `server/crates/sim/src/radar.rs` (new file, complete)

Pure logic, no server deps, wasm-safe. Doc-comment every public item. Add `pub mod radar;` to `lib.rs`
in alphabetical order (after `pattern`, before `rules`).

```rust
//! Radar modules (T-086): what a player is allowed to see, and how often.

/// Range of the gift arrow, in units.
pub const GIFT_ARROW_RANGE: f32 = 60.0;
/// Ticks between enemy-radar pings (10.0 s at 20 Hz).
pub const ENEMY_RADAR_COOLDOWN_TICKS: u32 = 200;
/// Ticks a ping stays visible (2.0 s at 20 Hz).
pub const ENEMY_RADAR_PING_TICKS: u32 = 40;
/// Radius of an enemy-radar ping, in units.
pub const ENEMY_RADAR_RADIUS: f32 = 30.0;
/// Radius of the ground-hazard overlay, in units.
pub const HAZARD_RADAR_RADIUS: f32 = 18.0;

/// The three purchasable modules.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum RadarModule { GiftArrow, EnemyRadar, HazardRadar }

impl RadarModule {
    /// Every module, in content order.
    pub fn all() -> [RadarModule; 3];
    /// Map a shop item id to its module.
    pub fn from_id(id: &str) -> Option<RadarModule>;
    /// The shop item id that grants this module.
    pub fn id(self) -> &'static str;
    /// Registry enemy ids this module counters (never empty).
    pub fn counters(self) -> &'static [&'static str];
}

/// A player's owned modules and the enemy-radar cooldown.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub struct RadarState { /* owned: [bool; 3], cooldown: u32, ping: u32 */ }

impl RadarState {
    /// Grant a module (idempotent).
    pub fn grant(&mut self, module: RadarModule);
    /// True when the module is owned.
    pub fn has(&self, module: RadarModule) -> bool;
    /// Advance one tick: the cooldown and the ping window both count down.
    pub fn tick(&mut self);
    /// Start a ping if the enemy radar is owned and off cooldown. Returns true when a ping started.
    pub fn fire(&mut self) -> bool;
    /// True while a ping is visible.
    pub fn ping_active(&self) -> bool;
    /// Ticks until the next ping is allowed (0 when ready).
    pub fn cooldown_left(&self) -> u32;
}

/// The nearest gift to `from` within [`GIFT_ARROW_RANGE`], with its distance.
pub fn nearest_gift(from: Vec3, gifts: &[Vec3]) -> Option<(Vec3, f32)>;

/// Indices of `points` within `radius` of `from`, in input order.
pub fn within_radius(from: Vec3, points: &[Vec3], radius: f32) -> Vec<usize>;
```

Tests: `from_id` round-trips `all()` and rejects `"radar_nope"`; every `counters()` is non-empty;
`grant` is idempotent and `has` reflects it; `fire` refuses without the module and while cooling
down, succeeds when ready, and `cooldown_left` counts down to 0; `ping_active` is true for exactly
`ENEMY_RADAR_PING_TICKS` ticks; `nearest_gift` picks the closest inside range, ignores gifts beyond
`GIFT_ARROW_RANGE`, and returns `None` for an empty slice; `within_radius` filters and keeps order.

## Part 3 - accept the new kind

- `server/crates/server/src/content.rs`: add `"radar"` to the known shop kinds (the match at ~line 310
  and the doc comment at ~line 154).
- `tools/validate-content.mjs`: add `"radar"` to `SHOP_KINDS` (~line 177). The "exactly 7 base items"
  rule counts `kind !== "counter" && kind !== "perk"`, so a `radar` item would land in the base set and
  break that rule - extend the filter to also exclude `"radar"`, and add a separate assertion that
  there are exactly 3 `radar` items.

## Part 4 - `server/crates/server/src/run.rs`

- `Run` gains `pub radar: sim::radar::RadarState`, initialised with `Default::default()` in `Run::new`.
- `Run::buy` (the shop purchase path): when the bought item's `kind == "radar"`, call
  `self.radar.grant(module)` where `module` comes from `sim::radar::RadarModule::from_id(&def.id)`.
  A radar item is a one-off: it is not pushed into `purchased_mods` and it applies no `mods`.
- `Run::tick_collapse` is not the right place; add the radar tick to whatever per-tick run method the
  server already calls every tick (find it - `Run::tick` or the game's tick), as `self.radar.tick()`.
- Add `pub fn radar_state(&self) -> sim::radar::RadarState` returning `self.radar`.
