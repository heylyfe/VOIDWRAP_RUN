## The measured gap this closes

`Run::new` sets `mode: sim::mode::DifficultyMode::Standard`, and **nothing in production ever
assigns `run.mode` again**. Every other assignment is in a test:

```
server/crates/server/src/game.rs:3142   g.run.mode = mode;          (test)
server/crates/server/src/run.rs:3756    run.mode = DifficultyMode::Chaos;    (test)
server/crates/server/src/run.rs:3765    run.mode = DifficultyMode::Random;   (test)
server/crates/server/src/run.rs:3785    run.mode = DifficultyMode::Extreme;  (test)
```

So `Extreme`, `Chaos` and `Random` are **unreachable in the shipped game**, even though the mode
gates the vote pool (`vote_pool_with`), the `extreme_finish` achievement, the Chaos shop-every-level
rule, and the matchmaker's published phase suffix (`phase_with_mode`). This is recurring defect
class #1 -- the piece exists but never reaches the player. The difficulty poll is the production
path it has been missing.

The theme half has a seam already: `chunk_weight(chunk, tier, high_rise)` in
`server/crates/sim/src/levelgen.rs:1182` is the single place chunk selection is weighted, and the
catalog already carries theme tags -- `theme:ruin` 4, `theme:hollow` 4, `theme:spire` 4,
`theme:garden` 3, `theme:ember` 4, `theme:machine` 3, `theme:void` 2, `theme:frost` 1 (25 chunks in
`design/chunks.json`). No new tags are needed.

## What to build, in this order

### 1. Protocol (additive only)

`protocol/schema.json` is the source of truth. Append, never reorder:

- `ClientMsg::Poll { option: u8 }` -- appended after `Debug`.
- `ServerMsg::PollOpen { options: Vec<PollOption>, countdown_s: u16 }`,
  `ServerMsg::PollState { counts: Vec<u32>, voted: Vec<u32>, seconds_left: u16 }`,
  `ServerMsg::PollResult { winner: u8, id: String, name: String, kind: u8 }` -- appended after the
  last existing variant.
- New type `PollOption { id: String, name: String, kind: u8 }`. `kind` is `POLL_THEME = 0` or
  `POLL_DIFFICULTY = 1`.
- New fixtures for each new message.

Then `just gen` and `just fixtures`. `node tools/protocol-gen.mjs --check` must pass. **Do not touch
`Vote`, `VoteOpen`, `VoteState` or `VoteResult`** -- the voting contract is frozen and the poll is a
separate message family, not a change to it.

### 2. Server

A pre-match poll session in the lobby, modelled on `VoteSession` in `server/crates/server/src/run.rs`
but a separate type. Opened when a run is created (level 1, `PHASE_ENEMY_DRAFT`), closed by its
countdown or when every connected player has voted. Ties broken deterministically from the run seed.
A rejoin re-offers the open poll and re-sends the surviving ballot -- the vote session already does
this and its test (`a_vote_survives_a_disconnect_and_is_re_offered_on_rejoin`) is the model.

Two poll kinds, offered in sequence: theme first, then difficulty.

### 3. Theme feeds tag weights

`Run` gains `theme_bias: Option<String>`. `chunk_weight` gains a multiplier when the chunk carries
the winning `theme:*` tag. **Default-neutral is a hard requirement:** with `theme_bias == None` the
weights must be byte-identical to today, so an unpolled run generates exactly the levels it
generates now. Prove it with a test that compares a fixed-seed level with and without a bias.

### 4. Difficulty sets the mode

The difficulty poll sets `run.mode` before level 1 begins. Legal only in the lobby. If the
matchmaker pinned a non-Standard mode for the room, the poll is not offered and the pinned mode
stands -- document what you find, because the mode currently only rides *out* to the matchmaker and
nothing reads it *in*.

### 5. Client

A poll panel in the lobby, wired the way the vote UI is (`web/src/hud/vote/` is the pattern:
`protocolAdapter.ts` + a component + a test). It must render nothing when no poll is open.

## Tests

- Server: open, tally, tie-break, countdown close, rejoin re-offer, a vote from a disconnected
  player surviving, and a poll that closes with zero votes leaving the run unchanged.
- Sim: a theme bias measurably shifts the tag mix over N seeds, and no bias is byte-identical to
  today.
- Web: the panel renders the options, sends `Poll`, and renders nothing when closed.

## Rules

- **Additive only.** No restructuring of the enemy registry, the pattern format, the voting
  contract, or `design/DEBUG_COMMANDS.md`.
- `just verify` is the gate. Protocol changes go through `just gen` + `just fixtures`, never by hand.
- No new crates or dependencies.
- **Anti-rabbit-hole: 3 attempts on a sub-problem, then park it.** If the protocol change turns out
  to need restructuring rather than appending, **park it and log it as a human decision** -- do not
  restructure a frozen contract.
- A documented PARTIAL is acceptable and better than a red gate: if the protocol, server and sim
  halves are green and the client panel is not, land the first three, park the panel, and say so in
  the ticket. Do not leave `just verify` red.
- Document every choice in the ticket. No human is available.

## Done when

A lobby poll opens, tallies, closes and applies; a theme bias measurably moves the tag mix; a
difficulty poll sets `run.mode` and the mode reaches the matchmaker's phase suffix; no bias is
byte-identical to today; `just verify` is green.
