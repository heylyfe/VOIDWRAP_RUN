# T-141 — End-to-end coverage for voting, shop and altars via the debug layer

**Cycle:** 17 · **Agent:** orchestrator · **Status:** PASS

T-139 established that the playthrough bots cannot reach level 2, and that the cause is
the starting-lives balance decision plus the bot's hold-still fallback. Voting, the
shop and altars all sit behind level 2, so **three shipped systems had no end-to-end
coverage at all** — the largest gap in the project.

The debug command layer (from the fix wave) can drive them directly, in singleplayer,
without needing a bot to survive a level. This ticket builds the kit that does it, and
fixes the one bug the kit found.

## The kit

`tools/debug-conformance/run.mjs` — 13 checks, speaking the real wire format through
`tools/voting-conformance/wire.mjs`, so a protocol change breaks it the same way it
breaks the voting kit. Wired into `just verify` (skips without a URL) and
`tools/verify-live.mjs`.

`wire.mjs` gained the two variants it was missing: `ClientMsg::Debug` (client variant
8) and `ServerMsg::DebugResult` (server variant 13).

| check | what it proves |
|---|---|
| `debug-state` | the readout parses: level, phase, currency, gifts_left |
| `debug-no-code` | no code at all is rejected with `debug commands are not enabled` |
| `debug-wrong-code` | a wrong code is rejected the same way |

Result: **13/13**.

## The bug the kit found

`debug_switch_level` called `start_level` but never refreshed the shop. `make_shop`
returns `None` at level 1 and was only ever called from `finish_level`, so **a tester
who jumped to level 10 still saw no shop at all** — the entire shop was unreachable
from the debug layer, which is exactly the system the layer exists to make testable.

The shop is priced by level bracket (the fix wave's T-C), so jumping levels has to
re-price it. One line in `run.rs`:

```rust
self.start_level(content, players.max(1));
self.shop = self.make_shop(content);
```

After the fix the kit sees a `Shop` frame with 11 items on join at level 6.

This is the same defect class the project keeps producing — **"the piece exists but
never reaches the player"** — this time in the debug layer rather than in level
generation.

## Two checks that had to be written honestly

- **Altars are placed per level**, so a given level may have none. The first version
  asserted `trigger_altar { id: 0 }` on level 5 and failed with `no altar 0 on this
  level`. The check now walks levels 5/7/9/12/15 and ids 0-3, and reports which one
  fired. A total miss is still a failure, not a skip.
- **The shop only exists from level 2 on**, and `set_phase` does not broadcast, so
  waiting for a `Shop` frame after forcing the phase could never work. The check now
  jumps to level 6 and observes the frame on join, which is the deterministic path.
