# T-107 — Generation consistency: random ramps and random lights

**Agent:** model:acpRegistry_mistral_vibe/deepseek-v4 (fresh thread)
**Owns:** pattern placement validation, light placement.
**Does NOT touch:** the ramp asset or slope collision (T-106), gift spawn logic
(T-112).

## Problem
Generation places ramps where they do not belong and lights inconsistently.

## Measured baseline (400 seeds, 6,000 level records)
- 141,243 ramp platforms placed. All have positive rise and `rise/run <= 0.5`,
  so the ramp *data* is well-formed — the inconsistency is in **anchoring**, not
  in the ramp numbers.
- The orientation half of this was a real generator bug and is fixed in T-106
  (`rotate_ramp_kind`). Re-measure after that fix before assuming anything else
  is wrong: a mis-sloped ramp also *looks* like a misplaced one.

## Work
1. **Orphaned ramps.** Define an orphan precisely: a ramp whose low edge is not
   supported by a platform top within `EPS` at the low-edge point, or whose high
   edge is not supported at the high-edge point. Note that a ramp legitimately
   rests on a large platform along its whole perimeter (see `contact_rise` in
   `levelgen.rs`), so the check must use the *low edge* sample, not the whole
   footprint. Add the assertion to `tools/pattern-audit/run.mjs` as a new metric
   line and require zero at 5,000 seeds.
2. **Light placement.** Lights must be deterministic per pattern spec: position,
   count and density come from the pattern's own data, never from global
   randomness. Add a `lights` block to the pattern format (additive — the format
   is frozen, so new optional fields only) and make the renderer read it. Assert
   in the harness that the same seed produces byte-identical light placement.
3. **Harness.** Extend the audit with `9.orphaned_ramps` and `10.light_stability`.

## Done when
Harness asserts pass at 5,000 seeds; no orphaned ramps; lights reproducible per
seed; gates green.

## Autonomous choices
- Treating the pattern format change as additive-only, per the frozen-contract
  rule: a new optional `lights` field, never a restructure of existing fields.
- Measuring before changing: the T-106 orientation fix may already account for
  most of the "random ramps" report.
