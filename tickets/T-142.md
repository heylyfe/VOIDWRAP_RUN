# T-142 — Gift-rate check, and a reverted bot change

**Cycle:** 18 · **Agent:** orchestrator · **Status:** PASS (one change merged, one reverted)

Two attempts at the same problem: `level-progression` is always skipped, so a
traversal regression in level design would go unnoticed. One attempt worked, one did
not, and the one that did not was reverted rather than kept.

## Attempt 1 — the bot's hold-still fallback (REVERTED)

T-139 found that the edge probe's failure path is `blacklist the gift, return hold`:
a bot whose remaining gifts are all behind unprobeable gaps stands still for the rest
of the run. The obvious fix is to walk back toward the middle of the platform underfoot
instead of freezing — always safe, and it re-rolls which gift is nearest.

Implemented as a `retreat(pos)` helper used by both `hold` return sites. Measured over
two 8-client 90 s runs:

| | best client's gifts |
|---|---|
| baseline (before) | 40/88, 44/88 |
| with `retreat` | 25/88, 42/88 |

**No measured win.** The sample is small and the variance is large, but the change is
neutral-to-worse and the dominant blocker is the 6–7 deaths per run, not the freeze.
Per the standing rule that no change merges without a measured win, it was reverted
(`git checkout -- tools/playthrough/run.mjs`).

This is worth recording because the hypothesis was reasonable and the measurement is
what killed it. The freeze is real but it is not what limits gift collection.

## Attempt 2 — `gift-rate` as its own check (MERGED)

`level-progression` needs a completed level, which the bots cannot reach, so it is
permanently skipped. That means the playthrough's only signal about level traversal is
a number buried inside a skip message — a level change that made traversal much worse
would not fail anything.

`gift-rate` asks the question that does not need a completion: can the bots still move
around the level and pick things up at a reasonable rate?

```
PASS - gift-rate (best client collected 33/88 gifts (37.5%) in 90s; threshold >= 20%)
```

Measured 28–50% across runs, so the 20% floor leaves headroom for run-to-run variance
while still failing if traversal degrades badly.

**Negative test:** raising the threshold to 90% gives
`FAIL - gift-rate (best client collected 30/88 gifts (34.1%) in 60s; threshold >= 90%)`
and the run reports `8/12 checks passed`. The check has teeth.

## Tuning notes (not changed)

- The freeze is real but not the limiter. The limiter is deaths: 6–7 per 90 s run, and
  a run starts with 0 spare lives, so the first fall ends that player's run.
- `gift-rate` at 37.5% is a useful baseline for the owner's balancing pass: if a
  difficulty change drops this below 20%, the level has become meaningfully harder to
  traverse.
