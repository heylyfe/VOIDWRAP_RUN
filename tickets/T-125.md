# T-125 — `hazard:trampoline` was a tag the engine did not keep

**Cycle 12, refinement 2 of 3.** The same class of defect as T-122's tripmine
thinness, caught by the same metric.

## Measured before

```
PASS — 8.hazard_entities
       hazard:trampoline: 3 patterns tagged, 1 carry a TRAMPOLINE platform (33.3%)
       hazard:tripmine: 4 patterns tagged, 4 carry a TRIPMINE platform (100.0%)
       a tag with no entity is a promise the engine does not keep
```

The audit's own closing line names the problem. Two of the three
`hazard:trampoline` patterns carried **`JUMP_PAD`**, not `TRAMPOLINE`:

| pattern | tags | platforms |
| --- | --- | --- |
| `pa_garden_bounce` | `mech:bounce`, `hazard:trampoline`, `pad` | NORMAL, **JUMP_PAD**, NORMAL |
| `pa_machine_bounce` | `mech:bounce`, `hazard:trampoline`, `pad` | NORMAL, **JUMP_PAD**, NORMAL, **JUMP_PAD**, NORMAL |
| `ch24_cinder_switchyard` | `hazard:trampoline` | NORMAL, JUMP_PAD ×3, **TRAMPOLINE** |

A jump pad and a trampoline are different hazards with different arcs. The tag
said trampoline; the geometry said jump pad. Anything that reads the tag —
the pedestal curse options, the Extreme/Chaos frequency tables, the radar
module — was being told the wrong thing.

## Change — additive only

Both patterns gained a real `TRAMPOLINE` platform in the gap their jump pad
already launched across, so the bounce chain reads as intended rather than the
tag being quietly dropped:

- `pa_garden_bounce`: `TRAMPOLINE` at x −2..2, z 0..1.5, y 0..0.5 — the gap
  between the jump pad (ends z=0) and the upper deck (starts z=1.5, y 2.5).
- `pa_machine_bounce`: `TRAMPOLINE` at x −1.5..1.5, z −1..0.5, y 0..0.5 — the
  gap between the first jump pad (ends z=−1) and the second deck (starts
  z=0.5, y 2).

Neither platform overlaps an existing one; both touch their neighbours at a
face, which `validate-content` accepts.

## Measured after

```
PASS — 8.hazard_entities
       hazard:trampoline: 3 patterns tagged, 3 carry a TRAMPOLINE platform (100.0%)
       hazard:tripmine: 4 patterns tagged, 4 carry a TRIPMINE platform (100.0%)
```

Both hazards are now at 100 %. Pattern audit **16/16**, economy audit **9/9**,
`just verify` green.

## Tuning notes

- Trampoline is still only 3 patterns of 135 (2.2 %). Tripmine is 4. If either
  should be a real mode flavour, the lever is the Extreme/Chaos frequency tags
  rather than more patterns — but 3 is thin enough that a 20-level run may
  never see one.
- `pa_garden_bounce` is `min_level: 1`, so a trampoline can now appear on the
  first level of a run. That is a good thing for teaching the hazard, and worth
  watching for a difficulty spike at level 1.
- The audit line "a tag with no entity is a promise the engine does not keep"
  is doing real work. It found both of this cycle's content defects.
