# Ticket T-013: M1 3D scene components (platforms, gifts, beacon, chaser, blocky avatar)
Target: GLM

## Context
Next.js 16 client, React 19, TypeScript 6 strict (`noUncheckedIndexedAccess` on), three 0.187,
@react-three/fiber 9 (`useFrame`, `<mesh>`, `<boxGeometry args>`, `<meshStandardMaterial>` etc.), @react-three/drei 10
is installed but optional. Path alias `@/` → `web/src/`. Components render INSIDE an existing r3f `<Canvas>`; they
must not create their own Canvas, camera, lights, fog or background. World units: 1 unit ≈ 1 m, +Y up.

Protocol types available from `@/protocol/generated` (read-only):
```ts
export interface Vec3 { x: number; y: number; z: number; }
export interface Aabb { min: Vec3; max: Vec3; }
export interface Platform { id: number; kind: number; bounds: Aabb; }
```

Visual direction: maximalist, chromatic, slightly chaotic colour against a dark void (`#07060d`), high-contrast
silhouettes readable at speed. Palette (only these, plus white/black):
- platform top families (pick per platform deterministically from its id): `#3b2a6b`, `#1f4b7a`, `#5a1f5e`, `#20565a`
- platform edge glow / accents: cyan `#38e8ff`, magenta `#ff3db8`
- gift gold `#ffd23d` with ribbon magenta `#ff3db8`
- beacon cyan `#38e8ff` (open) / dim `#2a3550` (closed)
- enemy (chaser) danger red `#ff4d4d` with emissive glow
- player default body `#ff3db8`, head/hands `#ffd9b8`, legs `#2b2b4a`, face features `#07060d`

Performance: up to ~60 platforms, 5 gifts, 4 enemies, 8 avatars at 60 fps on a laptop. Prefer simple box/
octahedron geometry, `meshStandardMaterial` with `emissive` for glow (no post-processing in this ticket), no
textures, no shadows, no per-frame allocations inside `useFrame` (mutate refs).

## Task
Create these files (named exports only):

1. `web/src/scene/palette.ts` — the palette constants above as a typed `export const PALETTE = { ... } as const`,
   and `export function platformColor(id: number): string` returning one of the four top colours
   deterministically (`id` modulo 4, handling negative ids).
2. `web/src/scene/Platforms.tsx` — `export function Platforms(props: { platforms: readonly Platform[] }): JSX.Element`.
   One box per platform covering its AABB exactly (centre = midpoint, size = max − min), coloured with
   `platformColor(id)`, plus a thin emissive cyan/magenta (alternating by id) outline strip along the top edges
   (e.g. a slightly larger, 0.06-unit-tall box at the top face, or edge lines) so platform edges read clearly
   against the void. Memoise derived geometry data with `useMemo` keyed on `platforms`.
3. `web/src/scene/GiftBox.tsx` — `export function GiftBox(props: { position: Vec3; taken: boolean }): JSX.Element | null`.
   A 0.7-unit gold cube with a magenta ribbon cross (two thin boxes) and a small bow on top; slowly spins
   around Y and bobs ±0.15 vertically (`useFrame`, mutate a group ref). `position` is the gift CENTRE.
   Returns `null` when `taken`.
4. `web/src/scene/Beacon.tsx` — `export function Beacon(props: { position: Vec3; open: boolean }): JSX.Element`.
   `position` is the point on the platform top. A 0.4-radius, 6-unit-tall translucent pillar of light
   (`transparent`, `opacity` ~0.35 open / 0.12 closed, `depthWrite={false}`) standing on a small 1.4-wide base;
   cyan and pulsing (emissive intensity oscillates) when `open`, dim `#2a3550` and still when closed.
5. `web/src/scene/Chaser.tsx` — `export function Chaser(props: { position: Vec3 }): JSX.Element`.
   Enemy whose hit box is a 1×1×1 cube centred on `position`: a red emissive octahedron (radius ~0.6) that
   spins fast, surrounded by 3–4 small orbiting shards; must read as clearly hostile and different from gifts.
6. `web/src/scene/BlockyAvatar.tsx` — `export const AVATAR_HEIGHT = 1.8;` and
   `export function BlockyAvatar(props: { bodyColor?: string; moving?: boolean }): JSX.Element`.
   A classic blocky figure built only from boxes, with its FEET at the group origin (y = 0), total height 1.8,
   width ≤ 0.8 (shoulders) and depth ≤ 0.45: legs (2), torso, arms (2), head (cube ~0.5) with simple face
   features (two eye boxes and a mouth box on the −Z face; −Z is "forward"). Original design — no logos.
   When `moving` is true, swing arms and legs (sinusoidal, ±0.6 rad, opposite phase) in `useFrame`; when false
   ease them back to 0. `forwardRef` is NOT needed.
7. `web/src/scene/palette.test.ts` — vitest tests for `platformColor` (deterministic, always in the palette,
   handles negative ids and large ids).

## Constraints
- Create only the seven files above; modify nothing else. No new dependencies.
- No `any`, no non-null assertions outside tests, no default exports. Add `"use client";` to `.tsx` files.
- `import type { JSX } from "react";` for return types. Typed refs: `useRef<Group>(null)` with `import type { Group, Mesh } from "three";`.
- Must pass `tsc --noEmit`, `eslint .` (typescript-eslint strict + react-hooks recommended — note the
  `react-hooks/set-state-in-effect` and `react-hooks/refs` rules: never read/write `ref.current` during render,
  only in effects/`useFrame`/handlers) and `vitest run`.

## Acceptance criteria
- [ ] Platform boxes exactly match the AABBs (centre and size computed from min/max).
- [ ] `platformColor` deterministic, in-palette, safe for negative ids — tested.
- [ ] GiftBox returns null when taken; animation mutates refs only.
- [ ] Avatar feet at y = 0, height 1.8, face on −Z.
- [ ] No per-frame allocations in `useFrame` callbacks (no `new`, no object/array literals created per frame).
- [ ] tsc / eslint / vitest green.

Verification commands (run by OVERSEER): `pnpm --dir web exec tsc --noEmit`, `pnpm --dir web exec eslint .`, `pnpm --dir web exec vitest run`, then a visual check in the running client.
