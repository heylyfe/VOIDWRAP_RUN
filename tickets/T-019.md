# Ticket T-019: Coloured void atmosphere (sky dome, fog) and drifting debris
Target: DEEPSEEK

## Common context
Next.js 16 client, React 19, TypeScript 6 strict (`noUncheckedIndexedAccess`), three 0.187, @react-three/fiber 9
(`useFrame`, `useThree`), @react-three/drei 10 installed. Path alias `@/` -> `web/src/`. Components render inside an
existing r3f `<Canvas>`. Vitest runs in the NODE environment (no DOM, no WebGL): three's math/geometry classes work
there, but `document`/canvas do not.

Art direction (design/VISUAL_DIRECTION.md, excerpt): one hue family per level; checkerboard tiles are the signature
surface (1x1-unit world-aligned checks of the theme light/dark colours with subtle grungy/marbled noise; sides darker,
still checkered; thin glowing edge trims); the void is a coloured misty atmosphere (gradient sky dome with slowly moving
procedural clouds/marbling, heavy fog so distant platforms melt into the sky; black under ~20% of the frame); swarms of
small dark cubes drift and tumble through the void. Everything must be ORIGINAL procedural art - no image files.

`web/src/scene/theme.ts`:
```ts
// Typed access to design/palette.json (the single source of truth for colours).
import palette from "../../../design/palette.json";

export interface Theme {
  id: string;
  name: string;
  mood: string;
  sky: { zenith: string; horizon: string; cloud: string; cloudDark: string };
  fog: { color: string; near: number; far: number };
  tile: { light: string; dark: string; side: string; edge: string };
  accent: string;
  debris: string;
}

export interface CommonColors {
  gift: { body: string; ribbon: string; glow: string };
  beacon: { core: string; beam: string; closed: string };
  enemy: { body: string; glow: string; hazardRing: string };
  player: { body: string; skin: string; legs: string; face: string };
  ui: { panel: string; panelTint: string; text: string; counter: string; danger: string };
}

export const THEMES: readonly Theme[] = palette.themes;
export const COMMON: CommonColors = palette.common;

/** Theme for level `n` (1-based); level 0 or negatives behave like level 1. */
export function themeForLevel(n: number): Theme {
  const count = THEMES.length;
  const i = Number.isFinite(n) && n >= 1 ? (Math.floor(n) - 1) % count : 0;
  const theme = THEMES[i] ?? THEMES[0];
  if (!theme) throw new Error("design/palette.json has no themes");
  return theme;
}
```

## Task
1. `web/src/scene/rng.ts`: `export function mulberry32(seed: number): () => number` (returns floats in [0, 1)),
   deterministic. (If you need it, also `export function hashString(s: string): number` - 32-bit FNV-1a.)
2. `web/src/scene/Atmosphere.tsx`: `export function Atmosphere(props: { theme: Theme }): JSX.Element`.
   - Sets `<color attach="background" args={[theme.sky.horizon]} />` and
     `<fog attach="fog" args={[theme.fog.color, theme.fog.near, theme.fog.far]} />`.
   - Renders a sky dome: a sphere (radius 450, 48x24 segments) with `side={BackSide}`, `depthWrite={false}`,
     `fog={false}`, `frustumCulled={false}`, `renderOrder={-1}`, re-centred on the camera every frame (useFrame), using
     a `ShaderMaterial` written inline (GLSL strings in the file) with uniforms uZenith, uHorizon, uCloud, uCloudDark
     (THREE.Color, set from the theme and updated when the theme changes - no material re-creation), and uTime.
     Fragment: direction = normalize(world position - dome centre); base = mix(horizon, zenith, smoothstep(-0.15, 0.85,
     dir.y)); clouds = fbm value noise (4-5 octaves, your own hash-based noise in GLSL) of a slowly scrolling 3D domain
     (dir * 3.0 + vec3(uTime * 0.01, 0, uTime * 0.006)), giving soft billowy cloud shapes AND darker marbled streaks;
     colour = mix(base, cloud, cloudMask * 0.65) then darken toward cloudDark where a second, lower-frequency noise is
     high (marbling), strongest near the horizon, weaker straight up. Output linear colour appropriately (three's
     ShaderMaterial does not apply colour management automatically: include `#include <colorspace_fragment>` after
     setting gl_FragColor, or convert sRGB uniforms yourself - pick one and say which in NOTES).
   - uTime advances with clock time in useFrame (mutate the uniform, no allocation).
   - Dispose geometry/material on unmount.
3. `web/src/scene/Debris.tsx`:
   - `export interface DebrisItem { position: [number, number, number]; scale: number; spin: [number, number, number]; orbitSpeed: number; bobPhase: number }`
   - `export function debrisLayout(seed: number, count: number, center: { x: number; y: number; z: number }, radius: number): DebrisItem[]`
     pure + deterministic (mulberry32): positions in a thick shell around `center` between 0.55*radius and 1.15*radius
     horizontally, y within [-12, +18] of center.y; ~30% of items placed in small clusters (3-6 cubes near each other)
     so the void has swarms, not uniform dust; scale in [0.15, 0.9] skewed small; spin per axis in [-1.2, 1.2] rad/s;
     orbitSpeed in [-0.03, 0.03] rad/s around the vertical axis through `center`; bobPhase in [0, 2*PI).
   - `export function Debris(props: { theme: Theme; center: { x: number; y: number; z: number }; radius: number; count?: number; seed?: number }): JSX.Element`
     - ONE `InstancedMesh` of unit boxes, `MeshStandardMaterial` color `theme.debris`, roughness 0.6, metalness 0.2,
       plus a slight emissive of `theme.accent` at intensity 0.05 so cubes catch a rim of colour. Default count 140.
     - Each frame: orbit each item around the centre axis, bob it (sin, amplitude 0.6), tumble it; write matrices
       through a preallocated Object3D (or Matrix4/Quaternion/Euler) - zero allocations in useFrame; set
       `instanceMatrix.needsUpdate = true`.
     - Layout memoised on (seed, count, center, radius); dispose geometry/material on unmount.
4. `web/src/scene/debris.test.ts` (vitest, node): `debrisLayout` is deterministic for the same seed, differs for a
   different seed, respects the radius shell and y bounds, scale range and count; `mulberry32` outputs are in [0, 1).
