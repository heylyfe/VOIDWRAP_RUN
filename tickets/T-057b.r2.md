# Ticket T-057b r2: the platform shaders do not compile in the real game (WebGL)
Target: INKLING (max effort)

The packaged game was play-tested in headless Chromium (WebGL). The level never renders: three.js reports
`THREE.WebGLProgram: Shader Error 0 - VALIDATE_STATUS false` for the platform materials in
`web/src/scene/Platforms.tsx`. The fragment code injected via `onBeforeCompile` uses uniforms that are never declared
in the shader source (`uPillarColor`, `uCheckerA`, `uCheckerB`, `uCrumble`, `uBottomColor`, `uPadBase`, ...) and
varyings (`vStateF`, `vColor`) that may not be declared in both stages. vitest/tsc/eslint cannot catch this; only a
real WebGL compile does.

## Task
Fix `web/src/scene/Platforms.tsx` (and any helper it uses) so every material's injected GLSL declares all its uniforms
(`uniform vec3 uPillarColor;` etc. in the fragment/vertex header it is used in) and all varyings in BOTH the vertex
and fragment shaders with matching types, the per-instance attributes are declared in the vertex shader, and every
`shader.uniforms.X = ...` assignment matches a declaration. Prefer a single helper that builds the header from the
uniform map so they cannot drift again. Add a vitest that string-checks each generated shader chunk: every
identifier starting with `u` followed by an uppercase letter or `v` + uppercase that is USED is also DECLARED
(regex check), so this class of bug is caught in CI. Keep visuals and behaviour identical. Output complete files.
