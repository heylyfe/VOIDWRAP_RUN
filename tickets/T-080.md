# Ticket T-080: integration — pedestal pools, tag flow, synergy proof

The pieces exist but nothing connects them. This ticket is the wiring, and it is the wave's
end-to-end proof.

## What exists (verified)

- `design/ENEMY_REGISTRY.md` §9 defines the pool rules: `min_level`, `selection_cap`, tags, class
  interactions, and the overflow rule when every cap is exhausted.
- `design/content.json` has 20 enemies with those fields; `server/crates/server/src/content.rs`
  parses them into `EnemyDef`.
- `server/crates/sim/src/enemies/` has all eleven new brains, and `hazards.rs` steps them live
  through `step_registry_brain`. `HazardEffect::Overtuned` and `HazardEffect::Infect` exist and the
  server stores both on the Player.
- `server/crates/sim/src/enemies/blight.rs` exports `infection_pauses_timer(infected_ticks)`.
- `server/crates/sim/src/enemies/chorus.rs` exports
  `chorus_candidate_allowed(small_permanents, level)`.
- `server/crates/sim/src/pattern.rs` has `TagBag` / `TagBagConfig` (theme bonus, recent divisor,
  difficulty penalty) and `CompositionPlan::build_with_len`.
- `server/crates/server/src/run.rs` has `Run::drafted_enemies: Vec<String>` — the permanents.
- T-078 adds the voting core; T-079 adds the UI. Read their code, do not rewrite it.

## What to build

1. **Pedestal pools from the registry.** One function that, given the run's permanents, the level,
   the classes present and the mode, returns the eligible enemy ids: `min_level <= level`,
   `selection_cap` not yet reached by the permanents, class interactions respected (an enemy whose
   `class_interactions` marks a present class `immune` or `ignores` is still offered — only an
   explicit refusal excludes it; if the registry has no refusal vocabulary, say so in NOTES and
   offer everything that passes the first two filters). Overflow: when the eligible set is empty,
   return temporary enemies for the next level instead of a permanent. Unit-test the pool against
   the real `content.json`.

2. **Synergy proof, end to end.** Three tests that go through the live hazard pass, not the brains
   in isolation:
   - **PEAL ↔ COIL**: a player standing in Coil's shockwave gets OVERTUNED; the same player is then
     killed by Peal's ring. A player who never met Coil is never killed by Peal. (The sim half of
     this already passes in `sim/tests/hazards.rs`; prove the server half — the debuff survives the
     tick boundary and reaches `PlayerSense`.)
   - **BLIGHT pauses REWIND and KITE**: while `infected_ticks > 0`, Rewind's and Kite's signature
     timers do not advance. Wire `infection_pauses_timer` into the two brains' timer decrements and
     test it.
   - **CHORUS gate**: `chorus_candidate_allowed` is consulted by the pool builder, so Chorus is not
     offered below level 10 or with fewer than two `small` permanents, and is offered once both hold.

3. **Lobby poll → composition tags.** A lobby poll (T-079's widget) produces theme/difficulty
   choices. Feed them into the next level's `TagBag` weights: a chosen theme gets a large bonus for
   that level only, and the choice is consumed. Test that a poll for `theme:frost` produces a level
   whose plan is measurably frost-heavy versus the same seed without the poll.

4. **Lobby list shows the vote phase.** The matchmaker heartbeat already carries `{players, level,
   phase}`. Make `phase` reflect the vote window (`voting`) as well as the existing phases, so the
   lobby browser shows it. Server-side only; T-066's UI already renders whatever `phase` says.

## Hard constraints

- Touch `server/crates/server/src/` and `server/crates/sim/src/` only. Never `web/`.
- Protocol changes only through `just gen` + `just fixtures`; never hand-edit generated code.
- No new crates. No `unwrap` outside tests. Doc-comment every public item.
- Do not rewrite T-078's voting core or T-079's UI; extend them.

## Done when

- Two clients vote, the winner spawns on the next level and persists to the one after that.
- The three synergy tests pass through the live hazard pass.
- The lobby poll measurably shifts the next level's theme mix.
- `cargo test -p server` and `cargo test -p sim` green, `just verify` fully green.

## Output format

Complete files with `=== FILE: <path> ===` ... `=== END FILE ===`, and function replacements with
`=== FN: <path> :: <name> ===` ... `=== END FN ===`. Every file you touch, whole.
