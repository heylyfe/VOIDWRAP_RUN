# T-137 — `5.heights`: the last loosened threshold, fixed at the data

**Cycle:** 15 · **Agent:** orchestrator · **Status:** PASS

`5.heights` was the last metric in the audit whose threshold had been **raised to fit
the data** rather than the data fixed. It sat at 3.59% against a 5% ceiling, and the
5% ceiling existed only because the original 2% had been raised by owner decision on
2026-11-15 with the note "the offending heights live in the frozen
`design/chunks.json`, and this is a style rule, not a correctness rule".

That reasoning was sound at the time and still hid the problem: an aggregate rate
cannot show *where* the offenders are, so nobody knew whether 15,352 violations were
spread thin across the catalog (a style question) or concentrated in one chunk (a bug).

## Measure first

The metric now reports the split and the owners, the same way T-128 fixed
`5.reference-scale`:

```
PASS - 5.heights (adjacent surface deltas measured: 427434; outside [1, 6]u
  (flat continuations ~0u excluded): 15352 (3.59%) [too small: 15352, too large: 0];
  by pattern id: ch02_hollow_market:15352; threshold <= 5%)
```

Two facts fall out immediately:

1. **One chunk owns all 15,352.** Not a catalog-wide style drift.
2. **All of them are too small, none too large.** So this is not a "big drop" problem;
   it is entirely half-steps — deltas between 0.01 and 1.0 u.

## The bug

`ch02_hollow_market` is a `hub`-role bowl with `min_level: 1`, so it is placed in
3,838 of 6,000 levels. Its geometry:

- four outer ring boxes, top `y = 0`
- one bowl floor, `x 4-12 z 4-12`, top `y = -1`
- four rim strips inside the floor footprint, top `y = -0.5`

The strips sat exactly halfway between the ring and the floor. Ring-to-strip is a
0.5 u step and strip-to-floor is a 0.5 u step: **two half-steps per strip, four strips,
3,838 placements, 15,352 violations.** A 0.5 u step is below the 1 u minimum the
reference scale calls for, and it is the same half-step class T-119 removed from the
rest of the catalog — this chunk was missed.

## The fix

Raise the four rim strips from top `-0.5` to top `0.0`, flush with the outer ring.
Four numbers in `design/chunks.json`.

The bowl now reads as intended: a 4 u walkway at `y = 0`, a 2 u ledge at `y = 0`, and
a sunken 4x4 market square at `y = -1` with four 2x2 corner pockets. Every step is
exactly 1 u, which is the minimum the reference scale asks for and comfortably
walkable by the controller's step-up logic. The five pit gift slots at `y = -0.7` are
unaffected: they sit on the open floor at `-1`, and none of them is covered by a
strip.

## Threshold back to 0

With the data fixed, `HEIGHT_DIFF_RATE_MAX` goes from `0.05` to `0`. A half-step
anywhere in the catalog now fails immediately instead of hiding under 5% of 427,434
pairs. This is the same move T-127 made for `GIFT_INTERSECT_MAX`.

## Negative test

Reverting **one** strip to `-0.5` and re-running:

```
FAIL - 5.heights (... 3838 (0.90%) [too small: 3838, too large: 0];
  by pattern id: ch02_hollow_market:3838; threshold <= 0%)
RESULT: FAIL - 1 of 17 metric lines failed: 5.heights
```

3,838 is exactly the chunk's placement count, which confirms the arithmetic
(4 strips x 3,838 = 15,352) and confirms the metric names the offender.
