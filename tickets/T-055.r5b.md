# Ticket T-055 r5b: physics bot technique - walk-offs, stair steps, aimed jumps
Target: INKLING (max effort)

## Context
`server/crates/sim/tests/playthrough.rs` proves generated maps are playable with the REAL controller: per (seed,
level) it routes over `levelgen::platform_graph` to 8 seed-chosen gifts and the beacon. It still fails ~56 of 60
levels. A parallel ticket tightens the map rules (jumps only onto >= 2 u wide platforms, gap <= envelope - 1 u), so
pixel-perfect jumps disappear; the remaining failures are the bot's technique. Typical failing edges (count, gap,
rise, from size -> to size, kinds 0 normal / 2 pad):
@include tickets/T-055.r5.edges.txt

## Task (output the complete playthrough.rs as FILE; keep the test size and the failure messages)
1. Touching drops (gap ~0, rise <= -0.55, incl. -4.5 to -6): steer to a point on the LOWER platform's top that is
   beyond the current platform's edge by >= half-width + 0.3 u in the travel direction, keep full input until
   grounded on the target. Never jump on a drop.
2. Stair steps and narrow treads (1 u deep) up or down 0.5 u onto a big platform: same "beyond the edge" target;
   for step-ups rely on the controller's 0.55 u step-up (no jump).
3. Jumps (gap > 0): run-up along the line from the current platform's interior through the takeoff point toward the
   landing target's centre, take off at the edge (last 0.3 u), hold jump to full height when rise > 0, steer to the
   landing target's centre while airborne; release steering only when grounded on the target.
4. Jump pads: walk onto the pad's centre, then steer to the next platform's centre while airborne.
5. Detect and break oscillation (re-planning back and forth between two platforms): if the bot alternates between
   the same two platforms 4 times, re-plan excluding that edge for this leg.
6. Generated-levels test: run 10 seeds x levels 1..6 and print a summary line "generated levels played: N,
   failed: F"; the test passes when F == 0. On failure keep printing seed/level/platforms/edge geometry.
