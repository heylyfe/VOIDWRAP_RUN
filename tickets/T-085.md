# Ticket T-085: difficulty modes

Four modes chosen in the lobby before a run, threaded through the registry pools, the pattern engine
and the voting system, and visible in the matchmaker lobby list.

## The modes

- **STANDARD**: a pedestal vote every level (the owner's directive), normal pools. The default.
- **EXTREME**: harder pools (one extra copy allowed per enemy, enemies offered one level earlier),
  denser fog.
- **CHAOS**: a shop every level (including level 1), plus a chaos-exclusive curse pool.
- **RANDOM**: no vote at all - the server picks a pedestal option itself each level.

## What exists (verified against the tree)

- `server/crates/server/src/run.rs` owns run configuration. `Run` has `pub curses: Vec<String>`,
  `pub permanents: Vec<String>`, `pub level_num: u32`, `pub seed: u32`, and a private `rng: Rng`.
- `vote_pool` / `overflow_pool` (run.rs:285 / 311) are free functions taking
  `(entries, level, classes, permanents)`. **Do not change their signatures** - ~15 tests call them.
- `Run::open_vote` (run.rs:1017) builds the options and opens a `VoteSession`.
- `Run::make_shop` (run.rs:1139) returns `None` at level 1.
- `GameStateHandle` (matchmaker_client.rs:127) publishes `{players, level, phase}`; `phase` is an
  **opaque string** in the frozen matchmaker contract, so the mode rides there as a suffix.

## Part 1 - `server/crates/sim/src/mode.rs` (new file, complete)

Pure logic, no server deps, wasm-safe (see the crate header in `lib.rs`). Doc-comment every public
item. Add `pub mod mode;` to `lib.rs` in alphabetical order.

```rust
//! Difficulty modes (T-085): the run-shaping knobs chosen in the lobby.

/// The four modes. `Standard` is the default and changes nothing.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum DifficultyMode {
    #[default]
    Standard,
    Extreme,
    Chaos,
    Random,
}

impl DifficultyMode {
    /// Every mode, in content order.
    pub fn all() -> [DifficultyMode; 4];
    /// Map a lobby id (`"standard"`, `"extreme"`, `"chaos"`, `"random"`) to its mode.
    pub fn from_id(id: &str) -> Option<DifficultyMode>;
    /// The lobby id this mode is chosen by.
    pub fn id(self) -> &'static str;
    /// Extra permanent copies allowed per enemy (EXTREME +1, else 0).
    pub fn cap_bonus(self) -> u32;
    /// Shift applied to every enemy's `min_level` (EXTREME -1, else 0). Never below 1.
    pub fn min_level_shift(self) -> i32;
    /// Fog multiplier on top of the run's curse mods (EXTREME 1.25, else 1.0).
    pub fn fog_mul(self) -> f32;
    /// True when the lobby shop opens every level, including level 1 (CHAOS).
    pub fn shop_every_level(self) -> bool;
    /// True when the pedestal vote is replaced by a server pick (RANDOM).
    pub fn forces_random_pick(self) -> bool;
    /// The suffix appended to the matchmaker `phase` string: `""` for STANDARD, else `":extreme"`,
    /// `":chaos"`, `":random"`.
    pub fn phase_suffix(self) -> &'static str;
}
```

Tests: `from_id` round-trips `all()` and rejects `"nightmare"`; `cap_bonus`/`min_level_shift`/
`fog_mul`/`shop_every_level`/`forces_random_pick`/`phase_suffix` each return the documented value for
all four modes; `Default` is `Standard`.

### 2b. Mode-aware pools - NEW functions, keep the old ones

The existing `vote_pool` and `overflow_pool` stay exactly as they are and become thin wrappers, so
every existing test keeps compiling. Current bodies (verbatim):

```rust
pub fn vote_pool(entries: &[PoolEntry], level: u32, classes: &[&str], permanents: &[String]) -> Vec<PoolEntry> {
    let tag_counts = permanent_tag_counts(entries, permanents);
    let small = tag_counts.get("small").copied().unwrap_or(0);
    let mut pool: Vec<PoolEntry> = entries
        .iter()
        .filter(|e| e.min_level <= level)
        .filter(|e| e.id != "chorus" || chorus_candidate_allowed(small, level))
        .filter(|e| {
            let held = permanents.iter().filter(|id| id.as_str() == e.id).count();
            held < e.selection_cap as usize
        })
        .filter(|e| requires_satisfied(e, &tag_counts))
        .filter(|e| !class_excluded(e, classes))
        .cloned()
        .collect();
    pool.sort_by(|a, b| {
        a.min_level
            .cmp(&b.min_level)
            .then(a.content_order.cmp(&b.content_order))
    });
    pool
}
```

```rust
pub fn overflow_pool(entries: &[PoolEntry], level: u32, classes: &[&str], permanents: &[String]) -> Vec<PoolEntry> {
    let tag_counts = permanent_tag_counts(entries, permanents);
    let small = tag_counts.get("small").copied().unwrap_or(0);
    let mut pool: Vec<PoolEntry> = entries
        .iter()
        .filter(|e| e.min_level <= level)
        .filter(|e| e.id != "chorus" || chorus_candidate_allowed(small, level))
        .filter(|e| requires_satisfied(e, &tag_counts))
        .filter(|e| !class_excluded(e, classes))
        .cloned()
        .collect();
    pool.sort_by(|a, b| {
        b.min_level
            .cmp(&a.min_level)
            .then(a.content_order.cmp(&b.content_order))
    });
    pool.truncate(VOTE_POOL_OFFER);
    pool
}
```

Rewrite each as `vote_pool_with(..., mode: DifficultyMode)` / `overflow_pool_with(..., mode)` carrying
the body above with two changes, then make the old names delegate with `DifficultyMode::Standard`:

- the `min_level` gate becomes `e.min_level as i32 + mode.min_level_shift() <= level as i32`, clamped
  so a shifted `min_level` never drops below 1;
- the cap check becomes `held < (e.selection_cap + mode.cap_bonus()) as usize`.

Keep the chorus gate, the `requires` hooks, the class filter and both sort orders exactly as they are.
`overflow_pool_with` still ignores caps and still truncates to `VOTE_POOL_OFFER`.

### 2c. `build_vote_options` uses the mode

At run.rs:966 and :979 the two calls become `vote_pool_with(&entries, level, classes, &permanents, self.mode)`
and `overflow_pool_with(&entries, level, classes, &permanents, self.mode)`.

### 2d. RANDOM replaces the vote

In `Run::open_vote`, before building options: when `self.mode.forces_random_pick()`, draw one option
from the pool with the run's own `self.rng` (deterministic per seed), apply it through the existing
`apply_vote_outcome` path with a `VoteOutcome` you construct, and return `false` so no session opens.
No vote UI appears in RANDOM - that is the mode's whole point. Document the draw in NOTES.

### 2e. CHAOS opens the shop every level

In `Run::make_shop`, the level-1 early return becomes
`if self.level_num == 1 && !self.mode.shop_every_level() { return None; }`.

### 2f. EXTREME thickens the fog

`Run::tuning()` builds the movement multipliers. Multiply the fog density by `self.mode.fog_mul()`
wherever the run's `fog_density_mul` is applied, so EXTREME stacks on top of the curse mods.

## Part 3 - the matchmaker heartbeat (`server/crates/server/src/matchmaker_client.rs`)

The matchmaker contract is **frozen**: `POST /matches/{id}` takes exactly
`{secret, players, level, phase, joinable}` and `phase` is an opaque string. So the mode rides inside
`phase` as a suffix - no new field, no contract change, no `protocol/schema.json` change.

- `GameStateHandle` gains `mode: std::sync::atomic::AtomicU8` (0 = standard).
- `publish` gains a fourth parameter `mode: u8` and stores it.
- `snapshot` appends the suffix: `format!("{phase}{suffix}")` where `suffix` comes from
  `sim::mode::DifficultyMode` - map the stored `u8` back through `DifficultyMode::all()` by index and
  use `phase_suffix()`. An out-of-range index means standard (no suffix).
- `game.rs:1132` passes the run's mode index. The enum has no explicit discriminants, so do not cast
  it: use `sim::mode::DifficultyMode::all().iter().position(|m| *m == self.run.mode).unwrap_or(0) as u8`.

Existing tests in that file assert `phase == "playing"`; they must keep passing, which they will
because the default mode is STANDARD and its suffix is empty.
