## What to build

### 1. New file `server/crates/sim/src/achievements.rs`

A pure, data-driven achievement tracker. No I/O, no time, no randomness.

```rust
//! Achievements (T-088): data-driven milestones a run can unlock.
//!
//! Pure and deterministic: the tracker is a function of the events it is fed,
//! so the server and any replay of the same event stream agree exactly.

/// One achievement definition. `id` is the stable key the content file and the
/// client both use; never rename an id once shipped.
pub struct AchievementDef {
    pub id: &'static str,
    pub name: &'static str,
    pub description: &'static str,
}

/// Every achievement, in display order.
pub const ACHIEVEMENTS: &[AchievementDef] = &[ /* the 10 below */ ];

/// Something that happened in a run that might unlock an achievement.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum AchievementEvent {
    /// A player broke out of a Lure's pursuit window.
    LureEscape,
    /// A player survived a Chorus freeze.
    ChorusFreeze,
    /// A pedestal vote finished. `for_votes` is the winner's count.
    VoteWin { for_votes: u8, against: u8 },
    /// The run reached this level number.
    LevelReached(u32),
    /// A level was cleared without any player dying on it.
    LevelClearedNoDeath,
    /// A Wreath greater curse was removed.
    WreathRemoved,
    /// A player launched off a trampoline.
    TrampolineLaunch,
    /// A player disarmed a tripmine.
    TripmineDisarm,
    /// Every gift on a level was collected.
    AllGiftsCollected,
    /// A run in EXTREME mode ended.
    ExtremeRunFinished,
}

/// The set of achievements unlocked so far in one run.
#[derive(Debug, Default, Clone)]
pub struct AchievementTracker {
    unlocked: Vec<&'static str>,
}
```

`AchievementTracker` must expose:

- `pub fn new() -> Self` — empty.
- `pub fn observe(&mut self, event: AchievementEvent) -> Option<&'static str>` —
  returns the id **only when this event newly unlocks something**, `None`
  otherwise. Never unlocks the same id twice.
- `pub fn unlocked(&self) -> &[&'static str]` — ids in unlock order.
- `pub fn has(&self, id: &str) -> bool`.
- `pub fn code(&self, seed: u32) -> String` — a cosmetic death-screen code.

`code` format: `VW-XXXX-XXXX` (four chars, hyphen, four chars) drawn from the
alphabet `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (no `I`, `O`, `0`, `1` — they read
badly). It must be a pure function of `seed` and the unlocked id list, so the
same run always shows the same code. Use an FNV-1a 64-bit hash over the seed
bytes followed by each unlocked id's bytes, then take five bits per character.
With nothing unlocked, still return a well-formed code derived from the seed
alone.

### Unlock rules (implement exactly)

- `LureEscape` → `first_lure_escape`
- `ChorusFreeze` → `chorus_freeze`
- `VoteWin { for_votes, against }` → `landslide_vote` when
  `for_votes >= 5 && for_votes >= against + 4`
- `LevelReached(n)` → `level_20` when `n >= 20`
- `LevelClearedNoDeath` → `clean_level`
- `WreathRemoved` → `wreath_removed`
- `TrampolineLaunch` → `first_trampoline`
- `TripmineDisarm` → `first_disarm`
- `AllGiftsCollected` → `every_gift`

### 3. Tests (in the same file, `#[cfg(test)] mod tests`)

Write at least **10** tests covering:

1. A fresh tracker has nothing unlocked and `has` is false for every id.
2. Each of the 10 events unlocks exactly its own id.
3. `observe` returns `Some(id)` the first time and `None` on a repeat of the
   same event.
4. `landslide_vote` unlocks at exactly 5-1 and does **not** unlock at 4-1 or
   5-2.
5. `level_20` does not unlock at 19 and does unlock at 20 and at 25.
6. `unlocked()` preserves unlock order.
7. `code` is stable: the same seed and the same tracker give the same string.
8. `code` differs for two different seeds with the same tracker.
9. `code` matches the shape `VW-XXXX-XXXX` and uses only the allowed alphabet
   (assert every character after `VW-` is in the alphabet or is the hyphen).
10. `ACHIEVEMENTS` has exactly 10 entries, ids are unique, and every id is
    reachable by some event (drive each event through a fresh tracker and
    collect the ids).
