# Ticket T-088: achievements and death-screen codes

Data-driven achievements with a lobby badge display and cosmetic codes on the death screen.

## The achievements (at least these)

First Lure escape; survive a Chorus freeze; win a 5-1 vote; reach level 20; clear a level without
dying; first Wreath removal; first trampoline launch; first tripmine disarm; collect every gift on a
level; finish a run in EXTREME.

## Requirements

- Achievements live in `design/content.json` so `validate-content` gates them: id, plain name,
  description, and the trigger condition as data.
- The server evaluates triggers from run state and reports unlocks to the client.
- The lobby shows earned badges per player.
- The death screen shows a cosmetic code drawn from the achievement pool; codes round-trip (a code
  maps back to its achievement and is stable across sessions).
- Tests: each trigger fires exactly once, a code round-trips, and the death screen renders it.
- Plain names, check-names green.

## Output format

Complete files with `=== FILE: <path> ===` ... `=== END FILE ===`, or single functions with
`=== FN: <path> :: <name> ===` ... `=== END FN ===`. Allowed paths: `design/content.json`,
`server/crates/server/src/`, `web/src/`, `tools/validate-content.mjs`.

Do not touch `protocol/` unless a client-visible field is genuinely required; if it is, change
`protocol/schema.json` and note that the lead must run `just gen` and `just fixtures`. No new deps.

## Done when

`node tools/validate-content.mjs`, `node tools/check-names.mjs`, `cargo test -p server` and the web
suite pass, and clippy is clean.
