## F-115-1 — Debug commands mutate state but never push it (SEVERE, FIXED)

**Repro (E2E, tester panel):** unlock the panel, run `grant_gold 500` — the
server's currency changes but the HUD still reads 0. Run `switch_level 12` —
the server is on level 12 but the HUD still reads level 1. Every command that
changes run state appears to do nothing.

**Root cause:** `debug.rs` `execute` returned a `DebugResult` and nothing else.
The command mutated `RunState` but no `RunState` frame was broadcast, so the
client's mirror never updated.

**Fix:** `game.rs` now, on a successful command:
- `switch_level` → `self.respawn_all_and_broadcast()`
- everything else → `self.broadcast_run_state()`

**Tests added:** `a_successful_debug_command_pushes_the_new_run_state`,
`switch_level_pushes_the_new_level_and_puts_the_player_on_its_spawn`.

**Commit:** `b2eede2`

## F-115-2 — Shop prices flat across all levels (SEVERE, FIXED)

**Repro (economy audit):** simulate a 50-level run. Gift income grows with the
level (more gifts, bigger rewards) but every shop item costs the same at level
1 and level 40. By level 20 the player buys the entire shop every time; the
shop stops being a decision.

**Fix:** `run.rs` gained `price_mul(level) = (gift_target(level,1) /
gift_target(1,1)).clamp(1.0, 8.0)` and `scaled_cost(cost, level)`. All five
cost sites in `make_shop` route through it. Invariant: **price/income is
constant across brackets (≤ 5 % drift)** — the shop costs the same *fraction*
of a level's income at level 1 and level 40.

**Tests:** 5, including the drift invariant.

**Commit:** `ef99756`

## F-115-4 — The merge gate silently skips four of its five black-box kits (SEVERE, OPEN)

**Repro (verbatim from a green `just verify` run):**
```
node tools/matchmaker-conformance/run.mjs
  matchmaker-conformance: skipped (no matchmaker to test; set MATCHMAKER_URL=<base url> or pass --url <base url>)
node tools/voting-conformance/run.mjs
  voting-conformance: skipped (set VOTING_URL or pass --url)
node tools/economy-audit/run.mjs
  economy-audit: skipped (no level dump; pass --from <ndjson> or set ECONOMY_AUDIT_CMD)
node tools/playthrough/run.mjs
  playthrough: skipped (set PLAYTHROUGH_URL or pass --url)
```
All four print "skipped" and **exit 0**. `just verify` invokes all four with no
arguments. So the merge gate has been reporting green while four of its five
black-box kits never ran — only the pattern audit (which needs a dump too) and
the unit suites actually execute.

**This is the single most important finding in this log.** Every "gates green"
claim in this repo's history means "the unit suites and the static checks
passed", not "the game works".

**Impact:** the gate cannot catch a voting regression or a playthrough
regression. This is the single most important finding in this log — it means
every "gates green" claim in this repo's history is weaker than it reads.

**Why not fixed here:** making `just verify` require a live server would make
the gate depend on a running process, which breaks `just verify` on a clean
checkout and in CI. The conservative fix is a separate recipe, not a change to
the gate's contract.

**Disposition: PARKED for a human decision.** Two candidate fixes, both
contract changes:
1. Add `just verify-live` that starts the server, runs both kits with `--url`,
   and stops it. `just verify` stays hermetic.
2. Make the kits exit non-zero on "skipped" unless `--allow-skip` is passed,
   and have `just verify` pass `--allow-skip`.

Option 1 is the better shape. **This is the top item for the owner.**

## F-115-8 — Playthrough `level-progression` fails (MEDIUM, PARKED)

**Measured:** 8 clients, 60 s — highest level reached: **1**. The bot never
completes a level, so `draft`, `vote`, and `shop` all SKIP.

**Root cause:** the bot steers in a straight line toward the nearest gift. It
needs a faithful JS port of `edge_rise` / `contact_rise` / `surface_at` /
`design_max_gap` to navigate ramps and gaps. Straight-line steering dies on the
first gap.

**Disposition: PARKED.** This is a harness limitation, not a game bug — the
7 checks that do run all pass, and the voting conformance kit's real mode
passes 3/3 against the same server.
