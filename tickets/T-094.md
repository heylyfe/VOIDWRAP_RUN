## The real message vocabulary (authoritative)

Client → server (`encodeClientMsg`):

```
Hello       { protocol_version: u16, name: string }   // protocol_version is 8
ChooseClass { class: u8 }
DraftPick   { picks: Vec<u8> }
Vote        { option: u8 }
Ping        { t: u32 }
```

Server → client (`decodeServerMsg`):

```
Welcome    { protocol_version, player_id, tick }
RunState   { info: RunInfo }        // info.phase, info.level, info.lives, info.currency, ...
Draft      { enemy_picks, reward_picks, cards: Vec<DraftCard> }
VoteOpen   { level, options: Vec<VoteOption>, countdown_s }
VoteState  { counts: Vec<u32>, voted: Vec<u32>, seconds_left }
VoteResult { winner, id, name, kind, permanent }
Error      { code, message }
```

`VoteOption` is `{ index: u8, id: string, kind: u8 }`. `RunInfo.phase` uses the
protocol constants: `PHASE_ENEMY_DRAFT = 0`, `PHASE_PLAYING = 1`,
`PHASE_REWARD_DRAFT = 2`, `PHASE_OVER = 3`.

## What changes in the stub

The stub becomes a **self-driving** contract double: it owns level progression
because the real server does. On `Hello` it replies `Welcome` then `RunState`
(phase 0, level 1). It then advances on its own timer:

1. `RunState` phase 0 → after `LEVEL_MS` (default 150 ms, `VOTE_STUB_LEVEL_MS`
   overrides) send `RunState` phase 1 and a `Draft` with three cards.
2. On `DraftPick` from every connected client (or after `DRAFT_MS`), send
   `VoteOpen` for the current level with three `VoteOption`s drawn from
   `registry.mjs` respecting min level and selection caps.
3. Broadcast `VoteState` every 250 ms while the session is open.
4. After `countdown_s` seconds (default 2, `VOTE_STUB_COUNTDOWN_S` overrides),
   send `VoteResult` with the majority winner, then `RunState` for the next level
   and loop from step 1.

Keep every existing violation switch (`majority_inverted`, `tie_ignored`,
`cap_ignored`, `permanence_dropped`, `rejoin_forgotten`, `late_vote_accepted`) and
the `VOTE_STUB_VIOLATION` env var. Each must still break exactly its paired check.

## What changes in the kit

- Transport: send `encodeClientMsg(...)` as a **binary** frame; decode every
  incoming **binary** frame with `decodeServerMsg`. A text frame from the server is
  a FAIL naming the frame.
- Drop `start_run` / `start_level` entirely. The kit connects, sends `Hello`
  (protocol version 8), sends `ChooseClass` for each client, and then **observes**
  the stub's own progression.
- Keep all ten checks and their names exactly:
  `session-at-every-level`, `options-shape`, `majority-wins`, `tie-rules`,
  `permanence`, `cap-aware-pool`, `min-level-gate`, `overflow-temporary`,
  `rejoin-safety`, `countdown-late-vote`.
- Keep `--selftest` (spawn the stub on an ephemeral port, run the matrix, then run
  it once per violation and assert the paired check is among the failures) and
  keep `--url` / `VOTING_URL`.
- Add `--real`: a three-check smoke mode for a live server, because a real server
  cannot be driven through levels by a black-box client. The three checks are
  `real-welcome` (a `Welcome` with `protocol_version` 8 arrives and decodes),
  `real-runstate` (`RunState` arrives and `info.phase` is a known phase), and
  `real-vote-outside-session` (a `Vote` sent while no session is open yields an
  `Error`, not a silent accept). `--real` must not run the ten stub checks.
