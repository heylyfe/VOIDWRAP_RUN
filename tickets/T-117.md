# T-117 — `just verify-live`: close the gate hole

**Owner decision (2026-11-15):** take the recommended option — a new
`just verify-live` recipe that starts the server, runs the live kits, and stops
it. `just verify` stays hermetic.

## The defect (F-115-4)

`just verify` invoked four black-box kits with no arguments:

```
node tools/matchmaker-conformance/run.mjs   -> "skipped", exit 0
node tools/voting-conformance/run.mjs       -> "skipped", exit 0
node tools/economy-audit/run.mjs            -> "skipped", exit 0
node tools/playthrough/run.mjs              -> "skipped", exit 0
```

All four print "skipped" and exit 0, so the gate reported green while four of
its five black-box kits never ran. The pattern audit was not in the gate at
all. Every "gates green" claim in this repo's history meant "the unit suites
and the static checks passed", not "the game works".

## The fix

`tools/verify-live.mjs` (new, 184 lines) does the whole live pass:

1. `node tools/build-wasm.mjs`
2. `cargo build --release -p server`
3. `cargo run --release -p sim --example pattern_dump -- 400` → a **fresh**
   dump in a temp dir, so a stale dump cannot mask a generation regression
4. starts `server/target/release/voidwrap-server` with `VOIDWRAP_DEV` and
   `VOIDWRAP_DEV_CODE` explicitly cleared, and polls TCP 7878 until it accepts
5. runs, in order: pattern audit, economy audit, voting conformance `--real`,
   playthrough (8 clients, 60 s)
6. runs the matchmaker kit only when `MATCHMAKER_URL` is set — this repo ships
   no deployed matchmaker, so it cannot run by default
7. `taskkill /t /f` the server (SIGTERM elsewhere), prints a PASS/FAIL summary,
   exits non-zero if any step failed

`justfile` gained:

```
verify-live:
    node tools/verify-live.mjs
```

Flags: `--skip-build` (reuse binaries), `--seeds N` (smaller dump).

## Why a separate recipe and not a change to `verify`

Making `just verify` require a live server would break it on a clean checkout
and in CI, where nothing is listening. The gate's contract is "hermetic"; the
live pass is a different contract. Two recipes, two contracts, no ambiguity.

## Choices made

- **Fresh dump every run.** The dump is `include_str!`'d into the binary, so a
  stale dump is a real hazard (it has bitten this repo before). Generating it
  inside the script removes the failure mode.
- **Explicitly clear the dev env vars** for the server the kits talk to. A
  developer with `VOIDWRAP_DEV_CODE` exported would otherwise run the kits
  against a tester build, which is not what the gate should test.
- **Matchmaker is opt-in.** The kit needs a deployed service. Failing the gate
  on an absent external dependency would make the gate unusable; skipping it
  silently is what caused this ticket. So it prints an explicit skip line
  naming the env var.
- **Playthrough runs last.** It opens 8 clients; running it before the voting
  kit would leave connections that the voting kit's rejoin checks could see.

## Done when

`just verify-live` runs end to end and reports PASS/FAIL per step. Verified in
