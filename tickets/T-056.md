# Ticket T-056: Server integration for M3 - new enemies, two-phase levels (collect -> collapse), golden gifts
Target: INKLING (max effort)

## Context
You wrote the M2 server integration (T-045). M3 (design doc below; section 0 amendments are binding) changed the sim
crate, all merged and tested:
- `sim::hazards`: nine reworked enemies with a new API (shown below): `Hazards::step(...)` returns
  `Vec<HazardEffect>` (`Kill { player, cause }`, `Shove { player, vel, stagger_ticks }`), `pulse` for Bulwark,
  `views` fills EnemyView (state/target/prog/flags), `projectiles`, `tiles` (crumble + FRETTED). `EnemyParams` is now
  `{ behavior, speed_mul, size, grace_ticks }` with `BEHAVIOR_*` = content order (pallbearer..corrupter).
  `PlayerSense { id, feet, vel, warded }`. The old `Hazards::hit` and the old EnemyParams fields are gone.
- `sim::controller`: CLASS_BULWARK (`ward_frames`, `bulwark_pulse_frame(&state)`), jump pads, step-up, stagger
  (`stagger_frames`, set by the server with a knockback velocity), fretted tiles; `World::set_tiles`.
- `sim::levelgen`: chunk assembler; `generate_for(seed, level, players)` (gift count per amendment A3), the beacon on
  the spawn hub, `enemy_spawns` = the hub's 8 enemy slots.
- `design/content.json`: enemies with `params { speed, aggro, grace_s, size, behavior }` (speed = design main speed;
  use it only to derive `speed_mul = 1.0` x curses - the per-enemy speeds live in the sim), class `bulwark`, shop
  prices doubled.
- Protocol v7: Snapshot `level_phase` (LEVEL_COLLECT / LEVEL_COLLAPSE_PENDING / LEVEL_COLLAPSING), `golden_taken`,
  `collapse_ms`; ControllerState `ward_frames`, `stagger_frames`; EnemyView `target`, `prog`, `flags`; TILE_FRETTED.
The server currently does not compile against the new sim API - fixing that is part of this ticket.

## Task
1. Content: map the new enemy params (behavior string -> BEHAVIOR_* index = content order; `grace_s` -> ticks;
   `size` x enemy_size_mul curse; `speed_mul` = enemy_speed_mul curse) and the bulwark class; keep everything else.
2. Enemies: drive `Hazards` exactly through its API each tick (players = ACTIVE players' feet/vel, `warded` =
   `state.ward_frames > 0`; pickups = gift positions collected this tick; speed_mul = 1.1 in LEVEL_COLLAPSING else
   1.0). Apply effects: Kill -> the existing death path (lives / spectate) with the cause; Shove -> set the player's
   `state.vel = vel` and `state.stagger_frames = stagger_ticks * 3` (60 Hz frames per 20 Hz tick). Bulwark: when
   `bulwark_pulse_frame(&state)` is true for a player, call `hazards.pulse(enemies, feet + (0, 0.9, 0), 3.0)` and
   shove other ACTIVE players within 3.0 u away at 7 u/s with stagger 0.8 s (48 frames). Snapshot enemies from
   `hazards.views`, projectiles from `hazards.projectiles`. World tiles = hazards.tiles() merged with the collapse
   tiles (below; collapse wins on the same id). Enemy spawns from levelgen; extra copies per the escalation table.
3. Two-phase levels (design 1.4 + A6): phase LEVEL_COLLECT until every gift is collected; then LEVEL_COLLAPSE_PENDING
   for 3.0 s (broadcast `Notice { kind: NOTICE_EVENT, ids: ["collapse"] }`), then LEVEL_COLLAPSING: golden gifts
   exist at EVERY collected gift position (same gift ids; a golden is collected by touching it, `golden_taken` lists
   them, each worth 1 currency); the beacon (on the spawn hub, walk-in as today) opens when the collapse STARTS (at
   PENDING); collapse order: all non-hub platforms sorted by distance from the hub beacon descending (ties by id), 6
   batches, batch i starts its warning at i*D/6 where D = max(30, 52 - 2*(level-1)) s (level 17+: -3 s, floor 30;
   level 25+: -1 s per level beyond 25, floor 25); each tile shows TILE_WARN for 3.0 s (2.0 s from level 9) then
   becomes TILE_GONE; golden gifts on a gone tile vanish. `collapse_ms` = time until the last batch has fallen.
   Jump pads also fall. If nobody reaches the beacon and every active player is dead/fallen, the existing run-over
   flow applies; when the collapse finishes, players still out on the map simply fall. Level 1 has no enemies (plain).
4. Gifts: use `levelgen::generate_for(seed, level, number of players)`; the old separate golden-gift entries from
   levelgen no longer exist (all gifts are normal). Remove the old "golden gifts after normal" logic.
5. Escalation (design section 5 with amendment A4 - from level 4 on): implement the rows that affect the server:
   extra enemy copies at the listed levels, per-tile warning 2.0 s from level 9, collapse D adjustments, fog +25%
   at 12 / +15% at 18 (fog_density_mul in RunInfo), Moteling/Snapshrike/Turret/Mimic/Pallbearer variant numbers are
   inside the sim - skip them unless trivially exposed. Broadcast the milestone banner text as
   `Notice { kind: NOTICE_EVENT, ids: ["milestone_<level>"] }` at level start.
6. Keep everything else working (lobby, classes, shop, altars, multiplayer spectating, plain first round). Update
   existing tests where M3 changes behaviour; add tests for: phase transitions, golden gifts at collected positions
   and their value, collapse ordering and timing (farthest first, hub never falls), golden vanishing on a gone tile,
   beacon only open from PENDING on, Kill/Shove effects applied (stagger frames set), Bulwark pulse calls, D formula
   at levels 1/6/11/17/30.
