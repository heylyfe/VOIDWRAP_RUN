# Ticket T-027: Procedural level generator ("roads in the void")
Target: INKLING-DESIGN (max effort; implementation ticket authorised by the human)

## Context
VOIDWRAP RUN is a fast 3D platformer: every level is a sprawl of floating checkerboard platforms in a misty void.
Players spawn together on a shared spawn platform, collect all normal gifts (which then makes golden bonus gifts
appear and opens the exit beacon), and walk into the beacon. Falling into the void kills. Every level must be freshly
generated from a seed and MUST be completable - no unreachable gifts, no unreachable beacon, no "holes" in a road that
cannot be jumped.

Language: Rust 2024, crate `sim` (no external crates; depends only on the workspace crate `protocol`). You write ONE new
file `server/crates/sim/src/gen.rs`; OVERSEER adds `pub mod gen;` to lib.rs. Rules: no `unsafe`; no `unwrap()`/`expect()`/
panics outside tests (use fallbacks); clippy::all clean (e.g. `n.is_multiple_of(k)` not `n % k == 0`, collapse nested
ifs with let-chains); deterministic for a given (seed, level) - implement your own small PRNG (mulberry32 or splitmix32)
inside gen.rs; no global state. Generation runs only on the server, at most once per level, budget < 20 ms.
Return the COMPLETE file in a FILE block, no markdown fences inside the FILE block.

Protocol types (generated, read-only; they derive Debug, Clone, PartialEq - NOT Copy):
```rust
pub struct Vec3 { pub x: f32, pub y: f32, pub z: f32 }   // Vec3::new(x, y, z), Vec3::ZERO
pub struct Aabb { pub min: Vec3, pub max: Vec3 }
pub struct Platform { pub id: u16, pub kind: u8, pub bounds: Aabb }   // kind 0 = normal
pub struct Gift { pub id: u16, pub pos: Vec3, pub kind: u8 }          // pos = gift centre; kind 0 = normal, 1 = golden
pub struct LevelData { pub level: u32, pub seed: u32, pub spawn: Vec3, pub beacon: Vec3, pub kill_y: f32,
                       pub platforms: Vec<Platform>, pub gifts: Vec<Gift> }
pub const GIFT_NORMAL: u8 = 0; pub const GIFT_GOLDEN: u8 = 1;
```
Available helper (read-only): `sim::world::overlaps(a: &Aabb, b: &Aabb) -> bool` (strict overlap).

Movement envelope (the real controller; do not exceed it): run 9 u/s; a running jump clears a 4.0-unit horizontal gap at
equal height, or rises 1.5 units onto a platform up to 2.5 units away; any drop is survivable. Player box: 0.8 wide,
1.8 tall - every walkable top needs >= 2.4 units of free headroom above it (no platform above a walkable top closer than
2.4 vertically within its x/z footprint expanded by 0.5).

## Required API
```rust
pub const NORMAL_GIFTS: usize = 5;
pub struct GeneratedLevel { pub data: LevelData, pub enemy_spawns: Vec<Vec3> }

/// The lobby hub: only the spawn platform (plus optional purely decorative small floating slabs that are NOT
/// reachable and placed >= 6 units away), no gifts, beacon placed far below kill_y so it is unreachable.
pub fn hub() -> LevelData;

/// A fresh, completable level. Same (seed, level) -> identical output.
pub fn generate(seed: u32, level: u32) -> GeneratedLevel;

/// Full structural check used by generate() (retry on failure) and by tests. Err describes the first problem.
pub fn validate(level: &LevelData) -> Result<(), String>;
```

## Generation design (follow it; tune numbers within the given ranges)
1. **Spawn platform**: id 0, top at y = 0, 12 x 12, centred on the origin; `spawn` = (0, 0, 0) on its top. Nothing else
   within 3 units of its edges except the roads leaving it.
2. **Road graph**: grow a tree (with occasional loops when two roads end near each other) of pieces from the spawn
   platform. Piece types:
   - *Walkway*: long and narrow - width 2..3, length 6..18, axis-aligned along X or Z, thickness 1.
   - *Junction pad*: 4x4 .. 7x7, where roads turn or branch (1-3 outgoing roads).
   - *Stair run*: 2-4 consecutive short blocks (length 2..3, width 2..3) each rising or falling by 0.75..1.25.
   Each new piece attaches to the free side of an existing piece via a CONNECTION:
   - *flush* (touching edge, same top height - a continuous road; at least 60% of connections), or
   - *gap* (horizontal gap 1.2 .. maxGap at equal height, or rise 0.5..1.4 with gap <= 2.2, or drop 0.5..3.0 with gap <= 3.0).
   Pieces must not overlap or nearly touch anything except their parent/child at the connection: keep >= 1.5 units of
   horizontal clearance to every unrelated piece whose top is within 4.0 vertically, and respect the headroom rule.
3. **Difficulty scaling with `level`** (level 1 easy, level 30+ hard, clamp beyond 40): piece count ~ 12 + 1.2*level
   (cap 50); maxGap 2.5 at level 1 rising to 3.8 by level 25; gap-connection share from 15% to 40%; height range of tops
   from [-1, 3] at level 1 to [-6, 12] by level 30; branch probability rises (more maze-like "roads"). Never exceed the
   movement envelope at any level.
4. **Beacon**: on the top centre of the junction pad (or end piece) with the greatest path distance (sum of piece-to-piece
   steps) from the spawn platform.
5. **Gifts**: exactly NORMAL_GIFTS normal gifts (ids 0..5) on distinct pieces, spread out: prefer dead-ends and side
   branches, never on the spawn platform or the beacon piece; each at 1.0 above the piece top, at least 0.8 inside the
   piece's x/z edges. Golden gifts: 2 + level/4 (cap 8), ids continuing after the normal ones, kind GIFT_GOLDEN, on other
   pieces (prefer the farthest/hardest ones), same placement rule. All gift ids unique, in order.
6. **Enemy spawns**: 8 candidate points, each 2.0 above some piece top and inside its x/z extent, >= 15 units (3D) from
   `spawn`, >= 4 units horizontally from every gift and the beacon; prefer different pieces, spread out.
7. `kill_y` = (lowest platform bottom) - 12. Platform ids 0..n in order. `level`/`seed` fields set from the arguments.

## validate() must check (and your tests must exercise)
- ids unique and dense 0..n; platform 0 is the 12x12 spawn platform with top at 0 containing `spawn`;
- no two platforms overlap (strict); clearance + headroom rules;
- exactly 5 normal gifts, golden gift count as specified, each 1.0 above a platform top and >= 0.8 inside it;
- beacon on a platform top;
- REACHABILITY: directed graph A->B if the horizontal gap between their x/z rectangles is <= 4.0 and B's top is at most
  1.5 above A's top (any drop allowed). Every platform that holds a gift (normal or golden) and the beacon platform must
  be reachable from platform 0. And every platform must be reachable from platform 0 (no orphan decoration in real levels);
- kill_y at least 10 below every platform bottom.
generate(): build -> validate -> on Err retry with a derived seed (up to 24 attempts) -> if all fail, return a
deterministic simple fallback layout that passes validate (a straight multi-piece road with side pads holding the gifts).

## Tests (in gen.rs `#[cfg(test)] mod tests`)
- `validate(generate(seed, level).data)` is Ok for seeds 0..300 at levels 1, 5, 10, 20, 40 (it must not fall back
  for more than 2% of them - count fallbacks and assert);
- determinism (same inputs -> equal LevelData) and variety (different seeds -> different platform layouts);
- piece count and max gap grow with level; hub() has only spawn-related content and no reachable gifts;
- enemy spawn rules; golden gift counts; validate() rejects hand-made broken levels (an unreachable gift, an
  overlapping platform, a missing spawn platform).

## Acceptance criteria
- [ ] API exactly as specified; deterministic; < 20 ms per level (keep the algorithm simple: rejection sampling with
      bounded attempts, no unbounded loops).
- [ ] All validate() rules and tests above; fallback rate <= 2%.
- [ ] Layouts read as long narrow roads with junctions, branches and height changes - a maze of paths, not isolated pads.
- [ ] clippy -D warnings clean, cargo test green.
