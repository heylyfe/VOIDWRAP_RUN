Target: DEEPSEEK

## Context
Rust 2024 crate `sim` (depends only on workspace crate `protocol`). Pure, deterministic game-rule helpers used by
the authoritative server. Same float rules as before: only `+ - * /`, `sqrt`, `abs`, `min`, `max`, `clamp`,
comparisons — no trig, no randomness, no time.

Movement envelope for level design: a running jump comfortably clears a 4.0-unit horizontal gap at equal height,
or rises 1.5 units onto a platform 3.0 units away. A jump + dash clears up to 7.0 units. Nothing harder in M1.

## Task
1. New module `server/crates/sim/src/rules.rs` (add `pub mod rules;` to lib.rs):
   - `pub const GIFT_RADIUS: f32 = 1.1;` A gift is collected when the distance from the player centre
     (feet + (0, 0.9, 0)) to `gift.pos` is <= GIFT_RADIUS: `pub fn gift_touched(player_feet: &Vec3, gift: &Gift) -> bool`.
   - `pub const BEACON_RADIUS: f32 = 1.5;` and `pub fn beacon_reached(player_feet: &Vec3, beacon: &Vec3) -> bool`:
     horizontal (x/z) distance <= BEACON_RADIUS and `(player_feet.y - beacon.y).abs() <= 1.0`. `beacon` is the point
     on the platform top where the beacon stands.
   - Chaser enemy:
     ```rust
     pub const ENEMY_KIND_CHASER: u8 = 1;
     pub const CHASER_SPEED: f32 = 5.5;          // units/s, slower than the player (9.0)
     pub const CHASER_AGGRO_RADIUS: f32 = 22.0;  // only chases targets within this 3D distance
     pub const CHASER_HALF_SIZE: f32 = 0.5;      // hit box: cube of this half extent around pos
     pub const CHASER_GRACE_TICKS: u32 = 60;     // inactive for the first 3 s of a level
     #[derive(Debug, Clone, PartialEq)]
     pub struct Enemy { pub id: u32, pub kind: u8, pub pos: Vec3, pub home: Vec3, pub active_in: u32 }
     pub fn spawn_enemy(id: u32, kind: u8, pos: Vec3) -> Enemy;   // home = pos, active_in = CHASER_GRACE_TICKS
     /// One server tick (dt = 1 / TICK_HZ). `targets` are the CENTRES of living players.
     pub fn step_enemy(enemy: &mut Enemy, targets: &[Vec3]);
     pub fn enemy_touches(enemy: &Enemy, player_feet: &Vec3) -> bool; // its cube overlaps player_box(player_feet)
     ```
     `step_enemy`: while `active_in > 0`, decrement it and do not move. Otherwise pick the nearest target within
     CHASER_AGGRO_RADIUS (ties: lowest index) and move straight toward it by at most `CHASER_SPEED / TICK_HZ`
     (never overshoot: if closer than one step, move exactly onto it). It flies: no gravity, no platform collision.
     With no target in range it drifts back toward `home` at half speed (never overshooting). Unknown `kind`
     values do nothing.
2. Replace `server/crates/sim/src/levels.rs`:
   - Keep `pub fn bootstrap() -> LevelData` exactly as now.
   - Add `pub const LEVEL_COUNT: u32 = 3;` and `pub fn level(n: u32) -> LevelData` for n >= 1: designs 1, 2, 3 are
     hand-authored; n > 3 reuses design `((n - 1) % 3) + 1` with `level = n` and `seed = n`. n = 0 behaves like 1.
   - Add `pub fn enemy_spawns(n: u32) -> Vec<(u8, Vec3)>` (kind, position) using the same design mapping:
     design 1 -> one chaser, design 2 -> one chaser, design 3 -> two chasers, each >= 15 units (3D) from the spawn
     point, floating 2 units above some platform top.
   - Designs: floating platform paths in the void that read as a branching route, not a straight corridor.
     Design 1 easy (8-10 platforms, mostly flat). Design 2 adds height changes (+/-1.5) and one optional side branch
     holding a gift. Design 3 has two routes that rejoin plus one optional jump+dash shortcut gap (> 4.0 and <= 7.0
     units) that is never REQUIRED. Platform tops between y = 0 and y = 8, thickness 1.
     Every level: spawn on platform id 0 (spawn = a point on its top), exactly 5 gifts (ids 0..5) each floating 1.0
     above a platform top and inside that platform x/z extent, beacon on the top of the last platform (farthest along
     the route), `kill_y` at least 10 below the lowest platform bottom. Platform `kind` 0 = normal.
     Keep the data readable with a small private helper like the existing `slab`.
