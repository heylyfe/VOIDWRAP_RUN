# T-133 — Metric thresholds: four checks weaker than their own names

**Cycle:** 14 · **Agent:** orchestrator · **Status:** PASS

## Why

T-126 found `8.hazard_entities` passing when 1 of 3 tagged patterns carried the
entity. T-127 found `5.gift-spawn-safety` allowing 75 gifts of slack against a rule
stated as "never". Both were the same defect: **a threshold looser than the metric's
stated intent**, so the metric could not fail on the thing it existed to catch.

This ticket audited the remaining 7 economy metrics and 16 pattern metrics for the
same shape. Four were found.

## The four

### `4.greater_curse_rate` — measured definitions, not a rate

```js
metric(greater.length >= 3, '4.greater_curse_rate', ...)
```

The name says *rate*. The check counted **definitions**. A run could reach level 50
without ever being offered a greater curse and the metric would still pass.

Now: the drafts a 50-level run actually gets must be in `[3, 8]`, **and** the pool
must be at least as deep as the number of drafts, so a 50-level run is never forced
to repeat one. Measured: 6 greater curses, `GREATER_EVERY = 10` -> 5 drafts over 50
levels, 6 >= 5.

### `5.hazard_tags` — passed on a single placement

```js
metric(total > 0, '5.hazard_tags', detail)
```

`total > 0` passes if **one** hazard-tagged placement exists in 6,000 levels. A
hazard that appears in fewer than one level in five is effectively absent from the
game.

Now: every hazard tag must appear in **>= 20 % of levels**. Measured: trampoline
65.1 %, tripmine 57.4 %, crumble 47.8 %, fog 41.4 %.

### `7.patterns_per_level` — `median >= 3`

A game where every level is three pieces long would pass. Measured median is 32
(min 17, max 59).

Now: median in `[10, 60]`. Below 10 the composition engine has collapsed; above 60
the plan length is unbounded.

### `3.pedestal_pool` — only level 1

```js
if (atLevel(1) < 3) allOk = false;
```

A pool that never grew past three options would pass, which would make the
level-scaled pool meaningless.

Now four conditions per mode: `pool@1 >= 3` (a vote needs three options),
`pool@10 > pool@1` (the pool must widen with level), `pool@20 >= 10` (a deep run
needs real choice), and `capacity > pool@1` (overflow must not start before the pool
is used). Measured: pool@1 = 3 standard / 8 extreme, pool@10 = 19, pool@20 = 20,
capacity 26 standard / 46 extreme.

## Evidence — both new bands have teeth

**Greater-curse pool degraded** to 2 definitions (vs 5 drafts over 50 levels):

```
FAIL — 4.greater_curse_rate
FAIL — economy-audit (7/8 metrics)
```

**All hazard tags stripped from `patterns-a.json`** (the dump unchanged, so the
audit sees the real placement distribution against a degraded catalog):

```
FAIL — 5.hazard_tags
       hazard:fog: 1591 placements (10.7%), in 1159 levels (19.3%)
```

`hazard:fog` fell to 19.3 % of levels, just under the 20 % floor. Reverted, both
pass.

## Result

Economy audit **8/8** with the tightened thresholds. `just verify` green.

| metric | before | after |
|---|---|---|
| `3.pedestal_pool` | `pool@1 >= 3` | 4 conditions across levels 1/10/20 + capacity |
| `4.greater_curse_rate` | `definitions >= 3` | `drafts over 50 levels in [3, 8]` and `pool >= drafts` |
| `5.hazard_tags` | `total > 0` | every tag in `>= 20 %` of levels |
| `7.patterns_per_level` | `median >= 3` | `median in [10, 60]` |

## Tuning notes

- The `[10, 60]` composition band is set around the measured median of 32. If a
  future cycle deliberately changes level length, this band moves with it — but it
  should move because someone decided to, not because a metric drifted.
- The 20 % hazard floor is a judgement call. `hazard:fog` sits at 41.4 %, so there
  is 2x headroom; a hazard that drops below 20 % is one a player meets less than
  once every five levels, which is the point at which it stops being a mechanic.
- `4.greater_curse_rate`'s `[3, 8]` band is derived from `GREATER_EVERY = 10`, so it
  moves automatically if that constant changes.

## Choice log

- **Tightened rather than added metrics.** All four already existed and already
  printed the right numbers; only the pass condition was wrong. Adding new metrics
  would have left the weak ones in place.
- **Bands, not exact values.** `median >= 3` was too weak and `median === 32` would
  be too brittle. A band around the measured value catches collapse and runaway
  without pinning the design.
- **Negative-tested both new bands.** A threshold nobody has seen fail is a
  threshold nobody knows works.
