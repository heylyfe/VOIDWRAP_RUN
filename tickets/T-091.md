# T-091 — Balance first pass: close the gift-income gap

## The measured problem

`tools/economy-audit` reports, over 3,000 generated levels:

```
FAIL — 1.gift_income
       gifts per level: median 219, mean 229.81, min 91, max 474
       cheapest shop item: 16 currency
       levels of income to afford the cheapest item: 0.07
```

Currency is earned at `GOLDEN_VALUE = 1` per golden gift, and there is exactly one
golden gift per collected normal gift. So a level pays out **~219 currency** against
a cheapest shop item of **16**. One level buys roughly fourteen of the cheapest
item: the shop is a formality, not a decision.

The audit's pass band is 0.5–4.0 levels of income per cheapest item. The gap is
~14x, so a ±20% nudge is noise. This ticket scales the whole price surface by
**12x**, which is the conservative structural fix: it changes no level pacing, no
gift count, and no code path — only numbers.

Every shop entry's `cost` must land on one of those eleven values. Do not change
`stock`, `kind`, `id`, `name`, `flavor`, or `effect`.

### 2. `tools/validate-content.mjs` — widen the two cost bands

The validator currently pins prices to the old scale. Change exactly these two
lines (they are at lines 195 and 197):

```js
    if (!Number.isInteger(s.cost) || s.cost < 5 || s.cost > 80) err(`${w}.cost=${s.cost} must be an integer 5..80`);
```
becomes
```js
    if (!Number.isInteger(s.cost) || s.cost < 60 || s.cost > 960) err(`${w}.cost=${s.cost} must be an integer 60..960`);
```

```js
    if (s.kind === "life" && !(s.cost >= 50 && s.cost <= 70)) err(`${w}.cost=${s.cost} must be 50..70 for a life`);
```
becomes
```js
    if (s.kind === "life" && !(s.cost >= 600 && s.cost <= 840)) err(`${w}.cost=${s.cost} must be 600..840 for a life`);
```

Also update the comment on line 173 that explains the ceiling, so it still tells
the truth about the new scale.

### 5. Tests that assert old prices

`cargo test -p server` will fail wherever a test hard-codes a price. Find every
such assertion and update the expected number to the new scale. Do **not** weaken
an assertion to make it pass — change the number. If a test asserts a *relationship*
(e.g. "buying this leaves you with X"), recompute X from the new price.
