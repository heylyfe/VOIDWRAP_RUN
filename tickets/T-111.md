# T-111 — Tester panel UI

**Agent:** model:opencode/opencode/inkling-2-small-free (parallel instance, max effort)
**Dispatch ONLY after T-110's manifest merges.** Wire against the frozen manifest
only — do not invent commands.

## Panel
A dev panel for tester builds:
- LOCKED by default, unlocked via a code entry field that sends the code to the
  server for verification. **Never validated client-side.**
- Sections per command group: Enemies (spawn/despawn by registry with caps
  shown), Level (jump/seed/phase), Economy (gold, gifts, upgrades, curses),
  World (fog, altars, teleport), State (registry, pattern, vote readouts).
- Command history + output log.
- The panel hides itself automatically when a second player joins — singleplayer
  enforcement mirrors the server gate.

## Constraints
New files; extend existing panels without refactoring them. The panel renders
nothing in normal builds.

## Done when
Vitest coverage for every section plus the lock/unlock flow; panel renders
nothing in normal builds; E2E: unlock with the code, spawn an enemy, switch
level, grant gold; gates green.

## Autonomous choices
- Auto-hide on a second player rather than disabling controls: a visible but dead
  panel invites bug reports about a panel that cannot work.
