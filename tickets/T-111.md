# T-111 — Tester panel UI

**Agent:** model:opencode/opencode/inkling-2-small-free (parallel instance, max effort)
**Dispatch ONLY after T-110's manifest merges.** Wire against the frozen manifest
only — do not invent commands.

## Panel
A dev panel for tester builds:
- LOCKED by default, unlocked via a code entry field that sends the code to the
  server for verification. **Never validated client-side.**
- Sections per command group: Enemies (spawn/despawn by registry with caps
  shown), Level (jump/seed/phase), Economy (gold, gifts, upgrades, curses),
  World (fog, altars, teleport), State (registry, pattern, vote readouts).
- Command history + output log.
- The panel hides itself automatically when a second player joins — singleplayer
  enforcement mirrors the server gate.

## Constraints
New files; extend existing panels without refactoring them. The panel renders
nothing in normal builds.

## Done when
Vitest coverage for every section plus the lock/unlock flow; panel renders
nothing in normal builds; E2E: unlock with the code, spawn an enemy, switch
level, grant gold; gates green.

## Autonomous choices
- Auto-hide on a second player rather than disabling controls: a visible but dead
  panel invites bug reports about a panel that cannot work.

---

## Outcome — PASS (with one honest gap)

**Files.** `web/src/hud/debugPanel.ts` (pure logic, 22 vitest cases),
`web/src/hud/TesterPanel.tsx` (the component), plus wiring in
`web/src/game/session.ts` (`debugCommand` + the `DebugResult` case),
`web/src/game/store.ts` (`debugResult`) and `web/src/game/GameClient.tsx`.

**Renders nothing in a normal build.** The component returns `null` until a dev
presses **Ctrl+Shift+D**. There is no always-on affordance, no menu entry, and no
DOM node in the tree before the gesture. `isRevealEvent` lives in the pure module
so the gesture itself is tested.

**Locked by default, unlocked only by the server.** The lock screen takes a code
and sends it with a `state` command. `applyResult` sets `unlocked` only on an
`ok` answer, so a wrong code leaves the UI visibly locked. Nothing is validated
client-side: the client cannot know whether the route is open or how many players
are connected, and pretending otherwise would be a lie.

**Sections** per the ticket: Enemies (spawn/despawn), Level (jump/seed/phase/
teleport), Economy (gold, gifts, upgrades, curses), World (altars, fog), State
(readout). Each command opens a form built from its manifest arg spec, with
required/optional marked and a hint. Output log keeps the newest 50 lines with
ok/fail colouring.

**Singleplayer enforcement.** `panelVisible(playerCount)` hides the panel at 2+
players, mirroring the server gate. Documented as a courtesy, not a boundary: the
server rejects the command either way.

**Choices made without a human.**
- *Ctrl+Shift+D as the reveal gesture* rather than a URL parameter: a URL leaks
  into screenshots and shared links; a key combo does not.
- *The panel mirrors the manifest by hand* rather than fetching it. The manifest
  is a design document, not a runtime asset. `debugPanel.test.ts` pins the exact
  command-id list, so a manifest change without a panel change fails a test
  instead of silently 400ing.
- *Empty optional args are omitted, not sent as `""`/`0`.* The server treats a
  present-but-wrong-typed key as an error and an omitted key as "use the default",
  so omitting is the only correct encoding.
- *Renamed the component `TesterPanel`.* `GameClient.tsx` already had a
  `DebugPanel` (the bottom-left status readout) and Windows treats
  `DebugPanel.tsx`/`debugPanel.ts` as the same file.

**The gap.** The ticket asks for a browser E2E (unlock, spawn, switch level,
grant gold). I did not run one: there is no browser in this environment. What is
covered instead is the same path one layer down — `game.rs` tests connect, send
`Hello`, send `Debug`, and read `DebugResult` for the closed route, the dev flag,
the dev code, the singleplayer rejection, the rate limit, spawn/despawn and a
level jump. The WebSocket framing between that and the browser is covered by the
protocol golden fixtures. **A human should still click through the panel once.**

**Gate.** `just verify` green: 310 vitest (was 286), 36 test files, 147 server
tests, clippy `-D warnings`, eslint, tsc, validate-content 132 patterns,
check-names 612 files.
