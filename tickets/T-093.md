## The wire format (bincode 1.x, fixint, little-endian — authoritative)

| type | encoding |
|---|---|
| `u8` | 1 byte |
| `u16` | 2 bytes LE |
| `u32` | 4 bytes LE |
| `u64` | 8 bytes LE |
| `f32` | 4 bytes LE IEEE-754 |
| `bool` | 1 byte, 0 or 1 |
| `string` | `u64` LE byte length, then UTF-8 bytes |
| `Vec<T>` | `u64` LE element count, then each element |
| enum | `u32` LE variant index, then the variant's fields in declaration order |
| struct | fields in declaration order, no padding, no length prefix |

Reference implementation to port: `@include web/src/protocol/codec.ts`
Type shapes: `@include server/crates/protocol/src/generated.rs`

## The exact messages to support

`ClientMsg` variant indices (encode only):

```
0 Hello        { protocol_version: u16, name: string }
1 Inputs       { frames: Vec<InputFrame> }      // not needed; throw if asked
2 Ping         { t: u32 }
3 Restart      {}
4 DraftPick    { picks: Vec<u8> }
5 Buy          { item: string }
6 ChooseClass  { class: u8 }
7 Vote         { option: u8 }
```

`ServerMsg` variant indices (decode only):

```
0  Welcome    { protocol_version: u16, player_id: u32, tick: u32 }
1  Level      { data: LevelData }               // decode to {variant:"Level"} and stop
2  Snapshot   { ... }                           // decode to {variant:"Snapshot"} and stop
3  Pong       { t: u32 }
4  Error      { code: u16, message: string }
5  RunOver    { summary: RunSummary }           // decode to {variant:"RunOver"} and stop
6  RunState   { info: RunInfo }
7  Draft      { enemy_picks: u8, reward_picks: u8, cards: Vec<DraftCard> }
8  Shop       { items: Vec<ShopItem> }
9  Notice     { kind: u8, ids: Vec<string> }
10 VoteOpen   { level: u32, options: Vec<VoteOption>, countdown_s: u16 }
11 VoteState  { counts: Vec<u32>, voted: Vec<u32>, seconds_left: u16 }
12 VoteResult { winner: u8, id: string, name: string, kind: u8, permanent: bool }
```

`RunInfo`, `DraftCard`, `ShopItem`, `VoteOption` are structs — decode them fully
from `generated.rs`. For `Level`, `Snapshot`, `RunOver` you may stop after the
variant index and return `{ variant: "<Name>", truncated: true }`: the kit never
inspects them, and decoding a whole `LevelData` is wasted work. Say so in a
comment.

## Required exports

```js
export function encodeClientMsg(msg)            // msg = { variant: "Hello", ...fields } -> Buffer
export function decodeServerMsg(buf)            // Buffer -> { variant: "VoteOpen", ...fields }
export function tryDecodeServerMsg(buf)         // same, returns null instead of throwing
```

`decodeServerMsg` must throw a `RangeError` naming the variant and the field when
a buffer is short or a length prefix runs past the end. Never read past the end
of the buffer, never allocate from an unchecked length prefix (cap any `u64`
length at the remaining byte count before allocating).

## Self-test (required, no server, no network)

`node tools/voting-conformance/wire.mjs --selftest` must run standalone, print
one `PASS — <name>` or `FAIL — <name>` line per check, and exit 0 only when every
check passes. Cover at least:

1. `encode Hello` — exact bytes for `{protocol_version:1, name:"ab"}`:
   `00 00 00 00 | 01 00 | 02 00 00 00 00 00 00 00 | 61 62` (hex, 19 bytes).
2. `encode Vote` — `{option:2}` is `07 00 00 00 02` (5 bytes).
3. `encode DraftPick` — `{picks:[1,2]}` is `04 00 00 00 | 02 00 00 00 00 00 00 00 | 01 02`.
4. `encode Ping` / `encode Restart` / `encode ChooseClass` / `encode Buy` — exact
   byte vectors you compute by hand and assert.
5. `decode VoteOpen` — hand-built buffer decodes to the right level, option
   count, each option's `index`/`id`/`kind`, and `countdown_s`.
6. `decode VoteState` — `counts` and `voted` vectors of differing lengths.
7. `decode VoteResult` — including `permanent: true` and `permanent: false`.
8. `decode Error` — code and a multi-byte UTF-8 message.
9. `decode Welcome` / `decode Pong` / `decode RunState` / `decode Draft` /
   `decode Shop` / `decode Notice` — round-trip through a hand-built buffer.
10. `truncated buffer` — a `VoteOpen` cut short throws `RangeError`, does not hang.
11. `absurd length prefix` — a `Vec` claiming `2^40` elements throws `RangeError`
    without allocating.
12. `unknown variant` — variant index 99 throws `RangeError` naming the index.
